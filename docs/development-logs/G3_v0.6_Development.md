# G3 v0.6 Development Log
## 2026-08-30 — Architecture and Phase 1A Core

- Approved the Godot Frontend + Python Core architecture.
- v0.6 uses a clean data/settings namespace under `G3`; v0.5 test data is not migrated.
- Backend protocol is localhost-only WebSocket + JSON, protocol version 1.
- Added clean settings, paths, SQLite library schema, Game repository, terminal state, preview media pipeline, game process tracking, theme service, and Classic Violet theme manifest.
- Preview media resolves manual assets before automatic discovery. GIFs are expanded into cached PNG frames; non-OGV video is prepared for FFmpeg Theora/Vorbis transcoding with static fallback on failure.
- Added request/response correlation, handshake enforcement, backend event broadcast, and direct protocol smoke coverage.
- v0.5 remains a historical prototype and is not imported by the new Core.

## 2026-08-30 — Phase 1B Godot Games Shell

- Added the formal Godot 4.7 frontend project under `g3_frontend/`.
- Default window is borderless maximized, not exclusive fullscreen.
- Added clickable XMB sections: Games / Movies / Comics / Music / Search / System. Non-Games media sections remain explicit Phase 1 architecture slots.
- Games uses a straight single-row 3D carousel made from real `BoxMesh`/`QuadMesh` case geometry, with cover loading, thickness/spine, hover tilt, wheel/keyboard selection, side-case recentering, delayed single-click preview, and double-click launch.
- Added same-page preview panel with 400 ms settle delay, screenshot/GIF/OGV video paths, optional preview audio, and theme music ducking hooks.
- Added one GPU ambient shader containing four moving waves plus 36 procedural triangle/circle/square/cross symbols.
- Added state restore for last section/item, Backend Connected/FPS diagnostics, basic System page, and Add Game executable picker.
- During a launched game, Godot disables its render loop and hides the window; `game.exited` restores the maximized terminal and selected item.

## 2026-08-30 — Phase 1C Launcher Cutover

- Kept `run_windows.vbs` as the visible Windows entry but changed its target to `pythonw -m g3_launcher`.
- The Python launcher owns the Core/WebSocket server and supervises the Godot frontend process.
- Godot executable discovery priority is saved setting → `GODOT_EXE` → PATH → one-time Windows file picker; the selected path is persisted in v0.6 settings.
- `run_windows_debug.bat` now runs the same v0.6 launcher with a visible console.
- Package metadata is now `local-resource-terminal` version `0.6.0`; v0.6 dependencies are limited to Pillow and websockets, with no PySide6 / pytest-qt dependency carried from the QWidget prototype.
- Fixed setuptools flat-layout discovery by explicitly including only `g3_core*` and `g3_launcher*`, excluding Godot/tests/tools, and packaging `g3_core/schema.sql` explicitly.
- The packaging regression was reproduced before the fix; after the fix both editable install and wheel build succeed, and the wheel contains `schema.sql` plus the runtime modules.
- Current local checkpoint: **42 tests passing**, direct protocol smoke PASS, editable install PASS, and wheel build PASS.
- Formal Godot frontend has structural/static validation here; final Godot 4.7.2 runtime/FPS verification must be performed on Windows before calling Phase 1 complete.


## 2026-08-30 — Runtime Data Hotfixes v0.6.0.3–v0.6.0.4

## 2026-08-30 — 3D Composition Hotfix v0.6.0.5

- Windows runtime showed game data and selected titles correctly while 3D cases remained invisible.
- Root cause: the GPU ambient was implemented as a full-screen opaque CanvasItem layer, while the cases lived in the main 3D world; the composition could cover the 3D result.
- Ambient rendering now uses a spatial shader on a real QuadMesh behind the collection, sharing the same 3D depth buffer as the cases.
- The ambient quad automatically tracks viewport aspect and camera FOV, preserving the four waves and 36 procedural △○□× symbols.
- UI remains on CanvasLayer 10 above the 3D collection.

- Added Launch Profiles with `direct`, `launcher`, and `emulator` modes, separating launch executable from monitored executable.
- Added Windows process monitoring so launchers such as Mod Engine can exit while G3 waits for the actual game process; emulator profiles can append or substitute `{content}`.

## 2026-08-31 — G3 v0.6.1.5 Focus Readability / Metadata / Elevation Fix

- Browse pose returns to a front-facing `0°` yaw; hover alone adds a restrained ±7° yaw / ±3° pitch response. Preview drag inspection remains ±40° yaw / ±12° pitch and eases back to front.

- Implemented the right-click `编辑资料` flow end to end. A new `game_metadata` SQLite table stores developer, publisher, release year, tags, and notes; title/description/platform remain in their existing canonical tables.
