# G3 v0.6 Development Log
## 2026-08-30 — Architecture and Phase 1A Core

- Approved the Godot Frontend + Python Core architecture.
- v0.6 uses a clean data/settings namespace under `G3`; v0.5 test data is not migrated.
- Backend protocol is localhost-only WebSocket + JSON, protocol version 1.
- Added clean settings, paths, SQLite library schema, Game repository, terminal state, preview media pipeline, game process tracking, theme service, and Classic Violet theme manifest.
- Preview media resolves manual assets before automatic discovery. GIFs are expanded into cached PNG frames; non-OGV video is prepared for FFmpeg Theora/Vorbis transcoding with static fallback on failure.
- Added request/response correlation, handshake enforcement, backend event broadcast, and direct protocol smoke coverage.
- v0.5 remains a historical prototype and is not imported by the new Core.

## 2026-08-30 — Phase 1B Godot Games Shell

- Added the formal Godot 4.7 frontend project under `g3_frontend/`.
- Default window is borderless maximized, not exclusive fullscreen.
- Added clickable XMB sections: Games / Movies / Comics / Music / Search / System. Non-Games media sections remain explicit Phase 1 architecture slots.
- Games uses a straight single-row 3D carousel made from real `BoxMesh`/`QuadMesh` case geometry, with cover loading, thickness/spine, hover tilt, wheel/keyboard selection, side-case recentering, delayed single-click preview, and double-click launch.
- Added same-page preview panel with 400 ms settle delay, screenshot/GIF/OGV video paths, optional preview audio, and theme music ducking hooks.
- Added one GPU ambient shader containing four moving waves plus 36 procedural triangle/circle/square/cross symbols.
- Added state restore for last section/item, Backend Connected/FPS diagnostics, basic System page, and Add Game executable picker.
- During a launched game, Godot disables its render loop and hides the window; `game.exited` restores the maximized terminal and selected item.

## 2026-08-30 — Phase 1C Launcher Cutover

- Kept `run_windows.vbs` as the visible Windows entry but changed its target to `pythonw -m g3_launcher`.
- The Python launcher owns the Core/WebSocket server and supervises the Godot frontend process.
- Godot executable discovery priority is saved setting → `GODOT_EXE` → PATH → one-time Windows file picker; the selected path is persisted in v0.6 settings.
- `run_windows_debug.bat` now runs the same v0.6 launcher with a visible console.
- Package metadata is now `local-resource-terminal` version `0.6.0`; v0.6 dependencies are limited to Pillow and websockets, with no PySide6 / pytest-qt dependency carried from the QWidget prototype.
- Fixed setuptools flat-layout discovery by explicitly including only `g3_core*` and `g3_launcher*`, excluding Godot/tests/tools, and packaging `g3_core/schema.sql` explicitly.
- The packaging regression was reproduced before the fix; after the fix both editable install and wheel build succeed, and the wheel contains `schema.sql` plus the runtime modules.
- Current local checkpoint: **42 tests passing**, direct protocol smoke PASS, editable install PASS, and wheel build PASS.
- Formal Godot frontend has structural/static validation here; final Godot 4.7.2 runtime/FPS verification must be performed on Windows before calling Phase 1 complete.


## 2026-08-30 — Runtime Data Hotfixes v0.6.0.3–v0.6.0.4

- Windows runtime confirmed Game creation/database/WebSocket flow, but exposed Godot Variant conversion issues while constructing cases.
- Replaced runtime-facing `String(...)` Variant conversions with `str(...)` across Main, BackendClient, PreviewPanel and GameCase3D.
- Standardized optional media paths at the Python/Godot protocol boundary: missing cover/background/video/audio/logo are serialized as empty strings rather than JSON null.
- Added a defensive null guard in GameCase3D so malformed/legacy payloads cannot become the fake path `<null>`.

## 2026-08-30 — 3D Composition Hotfix v0.6.0.5

- Windows runtime showed game data and selected titles correctly while 3D cases remained invisible.
- Root cause: the GPU ambient was implemented as a full-screen opaque CanvasItem layer, while the cases lived in the main 3D world; the composition could cover the 3D result.
- Ambient rendering now uses a spatial shader on a real QuadMesh behind the collection, sharing the same 3D depth buffer as the cases.
- The ambient quad automatically tracks viewport aspect and camera FOV, preserving the four waves and 36 procedural △○□× symbols.
- UI remains on CanvasLayer 10 above the 3D collection.

## 2026-08-30 — Games UX / Diagnostics Pass v0.6.0.6

- Reframed the Games layout from a debug-centered model view into a collection composition: browse main case sits left/down of viewport center and shifts farther left for inline Preview.
- Current game title and playtime/platform caption now follow the selected 3D case in screen space instead of replacing the upper-left module heading.
- Preview opening fades the case caption out; closing Preview restores it. Blank Games-space click and Escape both close Preview, while clicks inside Preview or on a 3D case do not.
- Increased case depth, added a default restrained 8° yaw, widened the visible spine, and made hover rotation additive to the base yaw so the case reads as a physical object even while idle.
- Added Classic Cyan and connected theme manifest colors to the ambient shader, UI text accents, fill light, and GameCase materials. Existing pre-schema Classic Violet test settings migrate once to Classic Cyan; Violet remains installed.
- Added in-app Phase 1 status text plus `docs/v0.6/Phase1_Feature_Status.md` so runnable, testing, placeholder, and not-yet-implemented areas are explicit.
- Launch failures now log executable/cwd/args in `terminal.log`, print backend command exceptions to the debug console, push Godot-side request errors, and show the actual error message in the terminal UI instead of only `LAUNCH FAILED`.


## 2026-08-30 — G3 Games Vertical Slice v0.6.1

- Product working name changed to **G3**. Runtime directories are now `g3_core/`, `g3_launcher/`, `g3_frontend/`, `g3_tests/`, and `g3_tools/`; user data root is `%LOCALAPPDATA%\G3`.
- Classic Cyan remains the default theme.
- The selected game case composition moved to the left-side collection anchor under the XMB, matching the approved annotated layout; the case title/meta follows the selected case.
- Replaced procedural faux-case construction with a real GLB asset pipeline. G3 prefers `g3_frontend/assets/models/game_case.glb` and falls back to a small true-3D placeholder GLB until final art is supplied.
- Carousel virtualization keeps at most nine nearby case instances active, so large libraries do not render one 3D model per catalog item.
- Added Launch Profiles with `direct`, `launcher`, and `emulator` modes, separating launch executable from monitored executable.
- Added Windows process monitoring so launchers such as Mod Engine can exit while G3 waits for the actual game process; emulator profiles can append or substitute `{content}`.
- Added Chinese right-click management entry points and a Launch Profile editor. Metadata/media/remove entries are visible but intentionally marked as not implemented yet.
- Rewrote the Phase 1 feature map in Chinese so visible product status matches actual implementation maturity.

## 2026-08-31 — G3 v0.6.1.3 Standard Tall Case Integration

- Integrated the first user-authored physical case template at `g3_frontend/assets/models/cases/standard_tall.glb`.
- Formal Blender/GLB node contract is now Chinese-facing: `盒体` and `封面正面`; legacy `cover_front` / spine naming remains compatible.
- The standard case keeps real-world dimensions in Blender/GLB (about 135 × 190 × 15 mm) and is scaled 10x only at runtime to match the existing carousel presentation coordinates.
- Existing game `cover` paths are loaded dynamically and assigned to `封面正面`; no game-specific artwork is embedded in the shared GLB.
- Fixed the library-list cover contract: `cover.*` files auto-discovered beside the game executable are now exposed to the carousel, not only to Preview. Manual indexed covers still take priority.
- Old `game_case.glb` and the placeholder GLB remain as fallback paths only.
- Platform-to-case-template mapping is intentionally deferred until additional case templates exist; this patch validates the first reusable case + dynamic front-cover pipeline.


## 2026-08-31 — G3 v0.6.1.4 Physical Case Showcase Pass

- Windows screenshots confirmed the user-authored Standard Tall GLB and dynamic front-cover texture are loading, but the previous scene lighting flattened the opening recess, seam, and bevel details.
- Replaced theme-tinted metallic case materials with neutral non-metallic plastic; selected/hovered cases no longer use emissive glow that washes out hard-surface detail.
- Replaced the old directional + cyan Omni light pair with a restrained three-point product-light rig: warm key, cool fill, and theme-aware rim, plus weak neutral environment ambient light.
- Increased the standard display yaw from 10° to 20° so physical thickness and opening-side details remain readable in browse view.
- Preview focus now supports left-drag inspection on the selected case, clamped to ±40° yaw and ±12° pitch; a 7 px threshold preserves click/double-click semantics, and release eases the model back to the display pose.
- Added an always-visible interaction hint for focused case dragging.


## 2026-08-31 — G3 v0.6.1.5 Focus Readability / Metadata / Elevation Fix

- Browse pose returns to a front-facing `0°` yaw; hover alone adds a restrained ±7° yaw / ±3° pitch response. Preview drag inspection remains ±40° yaw / ±12° pitch and eases back to front.
- Preview focus now enlarges the selected case (`PREVIEW_SELECTED_SCALE = 1.52`, plus the existing selected emphasis) so physical-case details can be inspected rather than merely repositioned.
- The dynamic front cover is treated as an independent printed-art layer: unshaded, non-metallic, and multiplied to 0.88 brightness so product lights no longer wash out cover contrast.
- Product lighting keeps warm key / cool fill / theme rim but lowers ambient/key/fill energy and adds restrained SSAO (`radius 0.18`, `intensity 1.25`) to help opening recesses, seams, and bevels read.
- Fixed Windows elevation error `WinError 740`: a direct launch that explicitly requests elevation now dispatches the existing `runas` UAC path instead of wrapping the target in `cmd.exe start /wait`; session start waits for the real `monitor_exe`.
- Gameplay handoff no longer calls `hide()` on Godot's main window. G3 minimizes the main window before disabling the render loop, then restores maximized/borderless state when the monitored process exits.
- Implemented the right-click `编辑资料` flow end to end. A new `game_metadata` SQLite table stores developer, publisher, release year, tags, and notes; title/description/platform remain in their existing canonical tables.
- Added a Chinese metadata editor window and Preview text layout for platform/year/developer/publisher, description, tags, and personal collection notes.

## 2026-08-31 — G3 v0.6.1.6 UI Polish / Browse Layout / Acrylic Case Pass

- 对 v0.6.1～v0.6.1.5 的结构与交互问题做了一轮集中复查，当前仍然只聚焦 Games Vertical Slice，但把日志与交接信息补全到可续接状态。
- Games 浏览态布局改成更接近 G1 的“大封面居中轮播”：主盒回到屏幕中央附近，左右只保留少量邻近盒；进入 Preview 后，主盒明显左移并放大，为右侧详情区腾出完整空间。
- Preview 主盒放大系数提升到 `2.18`，悬停响应提升到约 `±12° / ±4°`，拖动检视范围提升到 `±55° / ±14°`，更适合观察开口、书脊和盒体细节。
- 游戏盒材质从普通白塑料进一步推进到“亚克力半透明”方向：盒体/书脊使用透明 + clearcoat 的非金属材质；封面仍保持独立无光照印刷层，避免被灯光洗白。
- 右键管理菜单从 `PopupMenu` 改为自建 `PopupPanel` 按钮面板，统一中文条目，并尽量规避原生子菜单在当前渲染链路下的发虚感。
- 顶部 XMB 文案改为中文：游戏 / 电影 / 漫画 / 音乐 / 搜索 / 系统；System 增加“退出 G3”按钮，同时支持 `Ctrl+Q` 快捷退出。
- Preview 详情区自身开始消费点击事件，修复“点击文字/详情也被当成空白返回”的问题；无媒体时显示“暂无预览素材”，有 GIF/截图/视频时不再额外悬挂状态提示。
- 新增 Preview 入场动画：文字从右向左淡入，媒体区自下向上淡入；保持原有预览音频与主题音乐 ducking 逻辑。
- 性能策略继续保守化：项目默认 `60 FPS` 上限，启用轻量 `MSAA 3D`，削弱背景 shader 的波浪/符号数量并移除中心 glow，场景环境光与 SSAO 进一步收敛；游戏运行时仍最小化主窗口并关闭渲染循环。
- 窗口切换逻辑改为延迟调用 `_enter_gameplay_mode()` / `_restore_from_gameplay()`，减少在后端事件回调瞬间直接改主窗口状态带来的风险。
- 版本号更新为 `0.6.1.6`，并补充了对应测试与交接文档。
