- Approved the Godot Frontend + Python Core architecture.
- v0.6 uses a clean data/settings namespace under `LocalResourceTerminal/v0.6`; v0.5 test data is not migrated.
- Backend protocol is localhost-only WebSocket + JSON, protocol version 1.

## 2026-08-30 — Phase 1B Godot Games Shell

- Added the formal Godot 4.7 frontend project under `godot_frontend/`.
- Default window is borderless maximized, not exclusive fullscreen.
- Added clickable XMB sections: Games / Movies / Comics / Music / Search / System. Non-Games media sections remain explicit Phase 1 architecture slots.
- Games uses a straight single-row 3D carousel made from real `BoxMesh`/`QuadMesh` case geometry, with cover loading, thickness/spine, hover tilt, wheel/keyboard selection, side-case recentering, delayed single-click preview, and double-click launch.
- Added same-page preview panel with 400 ms settle delay, screenshot/GIF/OGV video paths, optional preview audio, and theme music ducking hooks.
- Added one GPU ambient shader containing four moving waves plus 36 procedural triangle/circle/square/cross symbols.
- Added state restore for last section/item, Backend Connected/FPS diagnostics, basic System page, and Add Game executable picker.
- During a launched game, Godot disables its render loop and hides the window; `game.exited` restores the maximized terminal and selected item.

## 2026-08-30 — Godot 4.7.2 Parse Hotfix v0.6.0.1

- First Windows runtime revealed that `main.gd` depended on custom `class_name` types (`TerminalBackendClient`, `GameCarousel3D`, `PreviewPanel`) before Godot had those global classes available to the parser.
- `game_carousel.gd` had the same cross-script dependency on `GameCase3D` through typed arrays/casts.
- `main.gd` also used Python-style `String.casefold()`, which does not exist in GDScript; it now uses `to_lower()`.
- Runtime-facing scripts now instantiate explicitly preloaded scripts without cross-script custom type annotations/casts, so startup does not depend on Godot global class-cache ordering.
- Added `terminal_tests/test_godot_parse_regression.py` to guard both failure modes.
- After the hotfix: **44 tests passing**, protocol smoke PASS, Python compileall PASS. Windows Godot 4.7.2 runtime parse must be rechecked on the target machine before marking the frontend runtime gate complete.

## 2026-08-30 — Input Routing Hotfix v0.6.0.2

- Windows runtime successfully reached the v0.6 terminal shell (`BACKEND CONNECTED`, live FPS, GPU ambient), but mouse UI controls were not usable.
- Root cause: `GameCarousel3D._input()` ran before Godot GUI dispatch and unconditionally called `set_input_as_handled()` for every left click, including empty-library clicks and XMB/System button clicks.
- Carousel input now exits while hidden/empty and only consumes a left click when `_handle_click()` confirms that a 3D case was actually hit. Unrelated UI clicks are allowed to continue to Godot Buttons.
- Added `terminal_tests/test_godot_input_routing.py` with red/green regression coverage for the input-consumption rules.
- Input regression tests: **3 passed**; protocol smoke PASS. The full suite currently shows one pre-existing `game.exited` timing failure in this execution environment because spawned Python startup is delayed by spreadsheet runtime warmup; the same failure reproduces on the unpatched checkpoint and is unrelated to the Godot input change.
