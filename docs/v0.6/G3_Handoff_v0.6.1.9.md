# G3 v0.6.1.9 交接摘要

## 当前定位

这一版不是继续增加功能，而是根据 G1 实机/视频参考修正 v0.6.1.8 的四盒构图、窗口行为、滚动生命周期和右下导航可发现性。

## Games 浏览态

- 仍然最多 4 个盒，主盒固定第二槽。
- 槽位使用 viewport-relative X：约 `17% / 44% / 70% / 92%`。
- 主盒与副盒通过 **尺度 + Z 深度 + 亮度 + 朝向** 同时区分。
- 副盒朝相机轻微收角，右边缘盒不应再以刺眼白书脊作为主视觉。
- 窗口 resize / maximize 会重新计算槽位世界 X。

## 轨道

- 入场/离场位置按相机 FOV、viewport aspect 和目标 Z 计算，真正落在窗口之外。
- `_transitioning + _queued_steps` 保证轨道 step 串行执行；快速滚轮只排队，不叠加多套离场实例。
- 启动恢复上次选择时使用 `jump_to_index()`，不让应用启动后把整个库逐项动画一遍。

## 窗口

- 默认 `Windowed + bordered + resizable`，参考 G1 桌面窗口行为。
- Windows 自带最大化 / 还原 / 改变大小应可正常使用。
- System 保留“窗口 / 最大化切换”。
- 游戏会话前保存窗口模式 / borderless / size / position；返回时原样恢复。

## 导航

- 右下角有常驻 48 px 导航柄。
- hover 和 click 都能打开抽屉；离开面板后延迟收起。
- 抽屉与导航柄都相对于 G3 viewport，而不是物理显示器热角。

## 实机验收顺序

1. 普通窗口启动；拖拽改变尺寸；使用 Windows 最大化/还原。
2. 静止浏览时确认四盒从左到右真正占满窗口，并且左盒不被主盒遮住。
3. 确认副盒明显更暗，右边缘盒仍以封面为主、书脊不刺眼。
4. 快速连续滚轮 10～20 次，观察屏内是否仍出现第五盒/幽灵。
5. 检查右下导航柄 hover + click；进入 System 再返回 Games。
6. 在普通窗口和最大化状态分别进入 Preview，确认聚焦主盒尺寸和右侧详情没有被破坏。
7. 分别在普通窗口、最大化状态启动/退出游戏，确认 G3 返回原窗口状态。
