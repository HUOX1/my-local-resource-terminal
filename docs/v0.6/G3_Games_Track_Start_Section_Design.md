# G3 Games 轨道浏览与默认启动板块设计

日期：2026-08-31
目标版本：v0.6.1.8（基于 v0.6.1.7 实机反馈）
范围：Games 浏览层 / 聚焦层 / 启动板块设置

## 1. 目标

本轮不再继续微调当前“五盒对称轮播”，而是替换 Games 浏览层的空间叙事，使 G3 继承 G1 已经成熟的视觉语言，同时保留真 3D、实时灯光和 Godot 动画能力。

成功标准：

- 浏览态最多同时显示 4 个盒，主盒固定在第 2 位。
- 单帧构图故意不对称，主盒具有明显视觉冲击力，边缘盒暗示屏幕外仍有收藏队列。
- 向左/向右滚动时，所有盒严格沿同一方向运动；退出盒从对应边缘消失，新盒从相反边缘进入，禁止实例横穿整屏“传送”。
- 聚焦态与浏览态形成明确层级：当前主盒、详情与预览是交互前景，其他盒只作为不可点击的暗背景。
- 聚焦主盒维持当前足够大的尺寸，但整体向左下移动，避免与顶部导航、右侧文字和预览区越位。
- 游戏标题/平台/时间与 3D 模型投影解耦，使用固定 UI 锚点，不再因为模型缩放或旋转跑进封面。
- 启动 G3 时不恢复“上次顶级板块”，改为读取用户设置的默认启动板块；默认值为“游戏”。
- 仍保留“上次选中的游戏”记忆，使用户进入 Games 后可回到上次浏览的收藏。

## 2. 方案选择

### 方案 A：继续修补现有循环索引轮播

优点：改动小。
缺点：当前 `_relative_index()` + `wrapi()` 会天然把节点从左侧槽位重新映射到右侧槽位，动画层无法表达“旧盒退出、新盒进入”；对称布局和穿屏问题会反复出现。

结论：淘汰。

### 方案 B：4 个固定视觉槽 + 节点复用

优点：实现简单，最多只维护 4 个实例。
缺点：如果直接把槽位中的同一 Node 改绑到另一个游戏，仍可能出现封面/身份在运动中突变；需要额外处理换绑时机。

结论：可行，但不作为首选。

### 方案 C：方向明确的 4 槽“虚拟轨道”

每次移动都把“盒实例的生命周期”和“库索引”分开：离场实例走出屏幕后释放；新游戏从正确一侧创建并进入边缘槽。其余 3 个实例只向相邻槽平移。

优点：运动叙事最稳定，最接近 G1；以后扩展不同盒型、主题动画也最清楚。
缺点：比现有轮播多一层轨道状态管理。

**采用方案 C。**

## 3. 浏览态布局

### 3.1 四个槽位

从左到右定义：

1. `SLOT_LEFT_FAR`：左侧远盒
2. `SLOT_MAIN`：主盒，固定第 2 位
3. `SLOT_RIGHT_NEAR`：右侧近盒
4. `SLOT_RIGHT_EDGE`：右侧边缘盒，可部分超出屏幕

视觉原则：

- 主盒约占 1600×900 可用高度的 55%～62%。
- 左远盒、右近盒明显缩小并压暗；右边缘盒更小、更暗，可被窗口裁切一部分。
- 不追求左右对称。右侧保留“队列继续延伸”的空间感。
- 背景 Games 区域平均亮度降低，维持 Classic Cyan 身份但改成深青黑；主盒成为画面里最亮、最饱和的元素。

### 3.2 标题锚点

浏览态标题不再使用 `camera.unproject_position(case.global_position)` 实时追踪模型。

改为固定在 `SLOT_MAIN` 下方的 UI 锚点：

- 第一行：游戏标题
- 第二行：平台 · 游玩时间

盒体 hover / drag / scale 不改变文字位置。

## 4. 轨道运动模型

### 4.1 向右选择下一款

旧状态：

`左远 | 主盒 | 右近 | 右边缘`

运动：

- 左远盒继续向左滑出窗口，结束后释放。
- 主盒移动到左远槽。
- 右近盒移动到主盒槽，成为新主盒。
- 右边缘盒移动到右近槽。
- 新游戏从右侧屏幕外创建，滑入右边缘槽。

所有可见对象 X 方向一致，禁止某个实例从左边跨屏跑到右边。

### 4.2 向左选择上一款

完全反向：

- 右边缘盒向右退出并释放。
- 右近盒 → 右边缘槽。
- 主盒 → 右近槽。
- 左远盒 → 主盒槽。
- 新游戏从左侧屏幕外创建并滑入左远槽。

### 4.3 库首尾循环

游戏索引可以循环，但**视觉实例不能穿屏循环**。库索引 wrap 只用于决定“新生成的游戏是谁”，不直接决定现有 Node 的目标位置。

### 4.4 少于 4 个游戏

- 1 个：只显示主盒。
- 2 个：主盒 + 右近盒。
- 3 个：左远 + 主盒 + 右近。
- 4 个及以上：完整四槽。

不复制同一条记录来凑满槽位。

## 5. 聚焦态

### 5.1 前景层

单击主盒进入聚焦后：

- 当前主盒维持 v0.6.1.7 的大尺寸量级，不继续无上限放大。
- 主盒锚点整体向左下移动，顶部不侵入 XMB，右侧与详情区之间保留明显负空间。
- 主盒仍支持拖动旋转检视；松手回正面。

### 5.2 详情层

右侧详情区包含：

- 标题
- 平台 / 年份 / 厂商等资料
- 简介 / 标签 / 收藏备注
- Preview 媒体

详情区作为一个完整交互区域，点击其中任何文字或媒体都不触发退出聚焦。

### 5.3 背景收藏层

其他游戏盒：

- 大幅压暗、缩小、推远；仅提供“收藏仍在后方”的空间提示。
- 不参与 hover、左键、右键和拖动命中。
- 不允许与主盒几何穿插。
- 聚焦状态的游戏切换只允许滚轮 / 左右键等显式导航，不允许直接点击背景盒抢焦点。

### 5.4 返回

只有以下行为退出聚焦：

- `Esc`
- 点击主盒、详情区、背景盒之外的真正空白区域

## 6. 默认启动板块

### 6.1 设置模型

`TerminalSettings` 新增：

```text
default_start_section: games | movies | comics | music | search | system
```

默认：`games`。

旧的 `restore_last_section` 不再参与启动路由；为兼容旧 `settings.json`，加载时允许旧字段存在并迁移到新 schema，不能导致旧设置文件报 Unknown settings key。

`restore_last_item` 继续保留并生效。

### 6.2 System UI

System 增加“默认启动板块”选择控件，用户可选：

- 游戏
- 电影
- 漫画
- 音乐
- 搜索
- 系统

UI 中文，持久化值保持英文机器 ID。

### 6.3 启动顺序

后端连接后：

1. 读取 `settings.get`
2. 根据 `default_start_section` 设置顶级板块
3. 读取 `state.get` 只恢复 `last_item_id`
4. 如果启动板块是 Games，则恢复上次选中的游戏；否则保留该 ID，用户以后切回 Games 时仍可定位

退出前所在顶级板块仍可写入 state 作为诊断/未来用途，但不再控制启动首页。

## 7. 代码边界

预计主要修改：

- `g3_frontend/scripts/game_carousel.gd`
  - 从“相对索引布局器”改成“4 槽虚拟轨道”
  - 管理进入/离场实例和方向
- `g3_frontend/scripts/main.gd`
  - 固定浏览标题锚点
  - 聚焦布局与返回边界
  - 启动板块读取顺序
  - System 默认启动板块 UI
- `g3_core/settings.py`
  - settings schema 升级
  - `default_start_section` 校验与旧设置迁移
- `g3_tests/`
  - 轨道方向、四槽数量、标题锚点、聚焦隔离、设置迁移与启动路由回归测试

本轮不修改：

- GLB 模型几何
- SQLite 游戏库 schema
- Launch Profile / 游戏启动链
- Movies / Comics / Music / Search 的实际内容页

## 8. 测试与实机验收

自动测试必须覆盖：

- 可见槽位永远不超过 4。
- 主盒逻辑槽固定为第 2 位。
- 向右切换时退出实例只向左离场，新实例只从右进入；向左反之。
- wrap 到库首尾时仍保持正确运动方向。
- 聚焦态 hit test 只返回主盒。
- 浏览标题使用固定 UI 锚点，不依赖 3D 投影。
- 旧 settings schema 能迁移；默认启动板块为 `games`。
- `default_start_section` 非法值会被拒绝。
- `last_item_id` 仍能恢复。

Windows 实机重点看：

- 1600×900 下是否达到 G1 那种“大主盒 + 不对称收藏队列”的冲击力。
- 连续快速滚动时有没有盒子横穿屏幕或身份突然变化。
- 主盒与背景是否真正分层，Classic Cyan 是否仍有辨识度但不抢封面。
- 聚焦主盒是否左下得当，不碰顶部导航，与右侧资料有足够呼吸感。
- 默认启动板块切到不同模块后，重启 G3 是否严格按设置进入；切回 Games 是否仍定位上次游戏。
