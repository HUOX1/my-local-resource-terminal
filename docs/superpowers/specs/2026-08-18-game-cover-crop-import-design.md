# 游戏封面“裁剪导入”最小改动设计

## 目标

在游戏档案的“静态封面”一行增加“裁剪导入…”按钮，让用户选择一张包含完整盒装封面的图片，直接复用现有影片 Front 手动裁剪器，裁出 Front 后作为该游戏待保存的封面来源。

## 范围

- 只修改游戏档案 UI 与临时裁剪文件管理。
- 不新增数据库字段，不修改 JSON/SQLite schema。
- 不新增批量封面工具，不增加目录扫描，不增加自动识别平台。
- 保留现有“浏览…”导入已处理封面与“清除”行为。
- 原始图片永不修改。
- 最终正式封面仍由现有 `GameAssetService.import_cover()` 保存到 `game_assets/covers/<uuid>.<ext>`。

## 交互

“静态封面”一行变为：

`[路径/状态] [浏览…] [裁剪导入…] [清除]`

点击“裁剪导入…”：

1. 选择 JPG/JPEG/PNG/WebP 图片。
2. 打开现有 `ManualCoverCropDialog`。
3. 用户用红线选择 Front 起点；黄色安全边距与实时预览保持现有行为。
4. 裁剪结果先写到当前游戏档案窗口拥有的临时目录，不写入正式游戏资产目录。
5. 裁剪成功后，将临时裁剪结果设为 `cover_source`，并取消 `remove_cover` 标记。
6. 点击游戏档案“保存”时，现有 `GameCatalogService` / `GameAssetService` 将临时图片导入 UUID 命名的正式封面。
7. 保存成功或档案窗口销毁后，临时裁剪文件可清理；原始图片保持不变。

## 错误处理

- 文件选择取消：无变化。
- 图片无法读取：沿用现有裁剪对话框异常提示。
- 裁剪取消：保持当前待保存封面状态不变。
- 裁剪失败：显示警告，不改变当前封面。
- 游戏档案保存失败：临时裁剪结果仍保留到窗口关闭，以便用户修正后重试。

## 测试

- 源码回归测试确认游戏档案出现“裁剪导入…”入口并调用 `ManualCoverCropDialog`。
- 现有 `GigaCoverCropper` 单元测试继续覆盖“原图不变、只输出右侧 Front”。
- 完整 pytest 回归，Python 3.11 兼容检查，compileall。
- 当前环境缺少 PySide6 时，Qt UI 测试继续跳过，最终按钮与交互需要 Windows 实机确认。
