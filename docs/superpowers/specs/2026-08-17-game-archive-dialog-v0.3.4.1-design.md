# v0.3.4.1 游戏档案窗口收口设计

## 目标

把现有“查看详情”和“编辑游戏”两个重复窗口合并为一个 **游戏档案** 窗口，减少重复信息与纵向臃肿，同时保留现有游戏数据、启动、计时、截图浏览器和封面/GIF 管理能力。

版本号：**v0.3.4.1**。本版不升级到 v0.3.5。

## 范围

### 1. 右键菜单

现有：

- 查看详情
- 编辑游戏

改为：

- **游戏档案**

“添加游戏”仍使用独立的添加对话框，不与档案窗口合并。

### 2. 游戏档案窗口

采用三个页签：

- **资料**
- **游玩**
- **媒体**

窗口顶部保留“启动游戏”作为明确主要操作。

不再在档案窗口显示大型游戏封面；封面识别由主海报墙承担。

### 3. 资料页

资料页直接可编辑并保存：

- 游戏名称
- 系列
- 开发商
- 发行商
- 发行日期
- 标签
- 评分
- 收藏
- **作品介绍**（新增）
- **我的记录**（沿用现有 `notes` 数据，仅调整 UI 名称）
- 启动 EXE
- 计时 EXE
- 启动参数
- 工作目录
- 截图目录
- 静态封面路径 + 浏览/清除
- GIF 动态预览路径 + 浏览/清除

“作品介绍”用于描述游戏本身；“我的记录”用于用户个人心得、进度、配置说明等。

封面/GIF 清除行为保持 v0.3.3 已确认规则：清除档案引用并删除终端 `game_assets` 中的受管理副本，不删除最初导入的源文件。

### 4. 游玩页

只展示自动产生的游玩档案，不与编辑字段混在一起：

- 安装状态
- 累计游玩时长
- 游玩次数
- 首次游玩
- 最近游玩
- Session 历史（开始时间 / 时长 / 状态）

游玩数据在该页只读。

### 5. 媒体页

复用 v0.3.3 已实现的截图浏览器骨架：

- 上方主展示区
- 下方横向缩略图胶卷
- 图片单击切换展示
- GIF 选中时播放，切走时停止
- 双击调用系统默认程序打开原文件
- 刷新
- 打开截图目录

不增加 Overlay、主动截图、目录持续监听或第二阶段视觉动效。

### 6. 新增字段：`description`

`GameMetadata` 增加 `description: str`。

持久化：

- 游戏 JSON 保存 `description`
- SQLite `games` 表增加 `description TEXT NOT NULL DEFAULT ''`
- 数据库 schema version 从 2 升到 3
- 老数据库初始化时安全 `ALTER TABLE games ADD COLUMN description ...`
- 老 JSON 未包含该字段时按空字符串读取，不提升 JSON schema version，保持向后兼容

搜索暂不把 `description` 加入全文搜索，本版只做档案展示/编辑，避免扩大范围。

### 7. 保存行为

游戏档案窗口点击“保存”后：

- 使用现有 `GameCatalogService.update_game()` 更新 JSON + SQLite
- 保存成功后刷新当前记录与主海报墙
- 窗口继续保持打开并显示保存后的数据；不强制关闭
- 必填项仍为游戏名称、启动 EXE、计时 EXE

若启动 EXE 已失效但用户只是编辑其他资料，仍允许保存未安装档案；若用户主动浏览选择了新的 EXE，则由现有文件选择行为确保路径来自实际文件。

### 8. 非目标

本版不做：

- GOG/IGDB/RAWG 等在线游戏资料搜索
- Hero 背景图
- 商店宣传截图自动下载
- 2077 风格视觉包装
- 官方预告片
- 成就系统
- 游戏详情页动画
- 模拟器专项支持
- 影片详情页重构

## 测试要求

至少覆盖：

1. 老 JSON 无 `description` 可正常读取为空字符串；
2. 新 `description` 可 JSON 往返；
3. DB v2 初始化后新增 description 列并变为 schema v3；
4. repository 可写入/读取 description；
5. `GameCatalogService.update_game` 可修改 description 且不丢 notes；
6. UI 结构测试：游戏档案存在资料/游玩/媒体三个页签；
7. 资料页显示“作品介绍”“我的记录”，不再显示大型封面；
8. 右键菜单只保留“游戏档案”，不再同时出现“查看详情/编辑游戏”；
9. 媒体页继续复用现有截图浏览器能力；
10. 现有全部影片/游戏测试继续通过。
