# 影片作品与剧集归档设计

日期：2026-08-21  
目标版本：v0.4.3.1.1  
基线源码：v0.4.3.1.0

## 背景

当前影片模型是一条影片档案对应一个 `video_path`。v0.4.3.1.0 的扫描器已经能发现同一文件夹内的全部视频，但会把 `01`、`02`、`03` 分别创建为独立影片，因此海报墙出现重复作品，子文件名也无法匹配以作品文件夹命名的集中封面。

本次改造把影片域从“一条档案对应一个视频”升级为“一个作品包含一个或多个视频项”。普通单片同样使用该结构，只在界面上隐藏单集概念。

## 已确认的产品规则

1. 一个包含视频的文件夹代表一个独立作品。
2. 文件夹内的全部受支持视频均属于该作品，并按集数规则排序。
3. 普通单片在底层也是“作品 + 一个视频项”，但界面保持当前单片体验。
4. 海报墙只显示作品，不显示独立剧集海报。
5. 作品的默认 `cover_key` 和编号来自文件夹名称，不来自 `_01`、`_02` 等子文件名。
6. `_02`、`E02`、`EP02`、`S01E02` 等标记仅用于后台识别，不直接作为界面文案。
7. 档案页的多集区域只显示“第 N 集”按钮；技术参数由纯信息图标打开，不显示“剧集详情”等按钮文字。
8. 海报双击仍进入影片档案页面。
9. 多集作品的海报右键“播放”变成剧集子菜单；单片仍直接播放。
10. 当前由 v0.4.3.1.0 误拆出的剧集档案没有手工资料，可自动收拢。

## 范围

### 本次实现

- 作品与剧集的一对多模型。
- 数据库与永久 JSON 档案迁移。
- 按文件夹分组的扫描、匹配、离线更新和封面匹配。
- 常见集数标记解析及自然排序回退。
- 海报墙去重、档案页集数按钮、图标化详情入口、右键播放子菜单。
- 播放指定剧集，同时继续累计作品级播放次数和播放时长。
- 自动收拢本版本已产生且未经编辑的重复档案。
- 版本统一提升至 v0.4.3.1.1。

### 暂不实现

- 单集独立封面。
- 单集已看状态、单集播放次数或单集进度。
- 手工拖动剧集排序、手工拆分或跨文件夹合并作品。
- 预告片、花絮等额外媒体类型；同一作品文件夹内的视频统一视为视频项。
- 完整的多季管理界面。`SxxExx` 可用于稳定排序，但本版仍按一个线性剧集列表展示。

## 方案选择

采用“作品父记录 + 剧集子记录”。`movies` 保留作品级资料、封面和累计播放统计；新增 `movie_episodes` 保存每个本地视频及其媒体探测结果。

未采用以下方案：

- 在现有平面影片记录上增加分组 ID：会继续复制标题、封面、标签和统计，长期容易不同步。
- 仅多集作品使用新结构：会让扫描、播放、离线状态和界面永久维护单片/多集两套分支。

## 领域模型

### 作品

`MovieMetadata` 继续保存作品级永久资料：UUID、封面键、编号、标题、演员、系列、厂商、日期、标签、评分、收藏、备注、分类文件夹、累计播放统计和播放历史，并新增有序的 `episodes: list[MovieEpisodeMetadata]`。

`MovieRecord` 增加有序的 `episodes` 集合。作品运行时只承担封面和聚合状态：

- 任一剧集可用时，作品可用。
- 部分剧集缺失时，作品仍保留并可播放其他剧集。
- 全部剧集缺失时，作品离线。
- 单片兼容入口只在作品恰好有一个视频项时返回该视频；多集作品不得隐式选择第一集。

### 剧集

新增永久 `MovieEpisodeMetadata`：

- `uuid`
- `display_order`
- `episode_number`（无法可靠解析时为空）
- `season_number`（仅在明确出现 `SxxExx` 时保存）
- `source_name`（最后一次识别到的文件名，用于重连和档案保留）

新增运行时 `MovieEpisodeRuntime`：

- `video_path`
- `library_id`
- `availability_status`
- `subtitle_status`
- `duration`
- `width`、`height`
- `video_codec`、`audio_codec`
- `file_size`
- `last_scanned_at`

剧集元数据保存在 JSON，保证数据库丢失后仍能保留作品的剧集清单；路径和媒体探测结果保存在 SQLite，可通过重新扫描恢复。

## 持久化与迁移

### JSON 档案

影片 JSON `schema_version` 从 1 升至 2，并新增 `episodes` 数组。读取器必须兼容 v1：

- 每个 v1 作品生成一个确定性的旧版主视频项 UUID。
- 无法从 JSON 得知文件名时，`source_name` 允许为空。
- 原有作品资料、分类、播放统计和历史原样保留。
- 保存后写为 schema v2。

确定性 UUID 保证 JSON 迁移与 SQLite v6 迁移能指向同一个视频项，不依赖执行先后。

### SQLite

数据库 schema 从 6 升至 7，新增 `movie_episodes` 表并建立以下索引：

- `movie_uuid`
- `video_path`
- `library_id` 与可用状态
- `(movie_uuid, display_order)`

旧 `movies` 行中的视频路径和媒体字段复制到确定性的旧版主视频项。原列暂时保留以避免破坏性重建表，但不再是多集作品的权威数据源；作品封面路径仍保留在父记录。

`play_events` 和作品 JSON 的播放统计仍归属于作品，本版不增加单集观看进度。

### v0.4.3.1.0 重复档案收拢

扫描同一文件夹时，如果不同视频路径命中了多个作品，只在这些作品符合“自动生成且未经编辑”条件时自动收拢：标题、演员、系列、厂商、日期、标签、评分、收藏、备注、分类和播放统计均保持默认值。

收拢流程：

1. 优先选择 `cover_key` 已等于文件夹名称的作品，否则选择最早创建的作品作为父记录。
2. 将该文件夹的全部视频项写入父记录，并把 `cover_key` 与默认编号修正为文件夹名称。
3. 原子保存父记录 JSON，并在数据库事务中写入父记录及剧集。
4. 事务成功后才移除冗余的自动生成 JSON 和数据库父记录。
5. 任一步失败时保留旧档案，记录扫描错误，不删除本地视频或集中封面。

如果检测到任何已编辑档案，则不自动合并，继续以匹配歧义报告，避免覆盖用户资料。

## 发现、识别与匹配

### 文件夹发现

`DiscoveryService` 返回作品候选，而不是为每个视频返回独立作品候选。发现规则保持递归：遇到包含受支持视频的文件夹后，该文件夹即为作品边界，不再把其子目录作为同级作品继续扫描。

一个作品候选包含：文件夹路径、以文件夹名生成的作品键，以及有序的视频项候选列表。

### 集数解析

解析器按明确程度识别：

1. `S01E02` 等季集标记。
2. `E02`、`EP02` 等明确集数标记。
3. 文件名末尾由 `_`、`-`、`.` 或空格分隔的数字，例如 `作品_02`。
4. 纯数字文件名，例如 `02`。

匹配不区分大小写。解析成功时按季、集和自然文件名排序；未解析或出现冲突时使用自然文件名排序，并生成唯一的线性 `display_order`。界面优先使用唯一且可靠的 `episode_number` 生成“第 N 集”；未解析或编号冲突时改用 `display_order`，不暴露原始 `_02` 文本。

### 作品匹配

匹配优先级：

1. 任一视频项的规范化完整路径。
2. 已记录的视频文件名与集数身份。
3. 文件夹名称与离线作品的 `cover_key`。
4. 文件夹名称与离线作品的编号。
5. 新建作品。

同一作品内的视频项先按完整路径匹配，再按 `source_name` 和集数身份匹配；无法唯一匹配时新增视频项，不覆盖已有项。

扫描结束时仅将本次未发现的视频项标记为离线，并据此重新计算作品聚合状态。不能再以“未看到作品 UUID”直接把整个作品离线。

## 封面行为

- 作品封面只使用作品级 `cover_key`，默认值为文件夹名。
- 集中封面匹配不再使用 `_01`、`_02` 等子文件名。
- 生成式回退封面可使用第一个可用视频，但生成结果仍归属于作品。
- 封面工具的“仅扫描库内对应电影”候选词需包含作品键、作品编号、作品文件夹名及各视频源文件名，以兼容现有素材命名。
- 单张 Front 复制流程不因本次改造回退。

## 界面与播放

### 海报墙

- 列表模型只接收作品记录，因此同一文件夹只出现一张海报。
- 双击海报继续进入影片档案页面。
- 单片右键菜单保留直接“播放”。
- 多集作品右键“播放”为子菜单，按顺序列出“第 1 集”“第 2 集”等；离线项禁用。

### 影片档案页

- 单片继续使用现有布局和“播放影片”入口，不显示剧集区域。
- 多集作品显示紧凑的“剧集（N）”区域。
- 主视图只显示“第 N 集”按钮；点击按钮直接播放对应视频。
- 离线剧集按钮置灰且不可播放。
- 文件名、路径、时长、分辨率、编码、大小、字幕和离线状态不在主视图展开。
- 技术参数由一个纯信息图标打开；图标无文字标签，悬停提示“剧集详情”。详情窗口集中列出全部视频项，并提供打开所在文件夹和重新关联所需入口。
- 多集作品不使用含义不明确的父级“播放影片”按钮；播放必须指定视频项。

### 播放统计

播放服务接收作品 UUID 和目标视频项，使用该视频项路径启动播放器。播放次数、首次/最后播放时间和累计播放秒数继续写入作品，不展示单集进度。

## 错误处理

- 单个视频探测失败不能阻止同一作品其他视频项入库；失败项保留基础路径和可用状态，并将错误加入扫描摘要。
- 集数无法解析时按自然文件名稳定排序，不把解析失败当成扫描失败。
- 封面不存在时继续沿用生成封面或无封面状态，不影响剧集归类。
- 自动收拢遇到已编辑资料、多个不可判定父记录或持久化失败时停止收拢并报告歧义。
- 删除作品档案只删除作品和视频项档案，不删除视频、字幕或集中封面文件。

## 测试与验收

至少覆盖：

1. `01`、`_02`、`E03`、`EP04`、`S01E05` 与自然排序回退。
2. 一个文件夹三个视频只生成一个作品、三个有序视频项。
3. 单视频文件夹生成一个作品、一个隐藏视频项，旧单片播放体验不变。
4. 作品封面使用文件夹名匹配，不使用子文件名。
5. JSON v1 到 v2 迁移保留全部作品资料和播放历史。
6. SQLite v6 到 v7 迁移幂等，并把旧视频运行时迁入视频项表。
7. v0.4.3.1.0 未编辑重复档案自动收拢；已编辑档案不自动合并。
8. 重扫不重复创建作品或视频项，删除一个视频只把对应视频项离线。
9. 数据库删除后可从 JSON 重建作品和剧集清单，再通过扫描恢复路径。
10. 海报墙只有一张作品海报；档案页主视图仅显示集数按钮和纯信息图标。
11. 海报右键播放子菜单与档案页集数按钮播放正确文件。
12. 单集或全部离线时的按钮、聚合状态和错误提示正确。
13. 封面工具仍按作品匹配，并保留单张 Front 复制行为。
14. 所有版本展示与包元数据统一为 v0.4.3.1.1。
