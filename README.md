# 本地资源终端

一个面向 Windows 的轻量本地资源管理器。当前第一阶段包含两个彼此独立的资源领域：**影片**与**游戏**。

它不是 Jellyfin、Steam 或模拟器前端的替代品。核心目标是给自己的本地收藏建立一个长期可维护的私人档案终端：影片负责封面墙、资料、观看记录与外部播放；游戏负责手动建档、启动、游玩时长、GIF 预览与截图浏览。

> **v0.3.4.7 是第一阶段功能冻结基线。** 影片、游戏、计时、媒体、备份恢复、SQLite 重建、PS1/PS3 模拟器直启等关键链路已完成真实使用验证。之后第一阶段只修真实 Bug；第二阶段从审美积累与视觉主壳设计开始。


**v0.3.4.7 备份恢复锁定修复：** SQLite 连接在离开数据库上下文时明确关闭，修复 DATA 已存在时恢复备份覆盖 `library.db` 可能触发 Windows 文件锁 / WinError 5 的问题。用户已实测“现存 DATA 直接恢复 → 自动重启 → 数据与游戏时间回到备份状态”成功。

**v0.3.4.6 游戏封面墙缩放流畅性修复：** 游戏静态封面与原始尺寸加入缓存，窗口拖动缩放不再反复从磁盘解码和高质量缩放；GIF 悬停预览仍保持逐帧播放。用户实测成功。

**v0.3.4.5 游戏封面裁剪导入：** 游戏档案的静态封面增加“裁剪导入…”，直接复用影片已经验证的 Front 手动裁剪器；不修改原图，不新增数据库字段。


**v0.3.4.4 封面墙缩放流畅性修复：** 影片封面墙不再在窗口拖动缩放的每次重绘中重复从磁盘读取封面尺寸、加载原始封面并执行高质量缩放；封面尺寸与显示用缩略图会在当前影片列表周期内复用，影片列表刷新时自动失效重建。封面比例、固定显示宽度和自然高度不变。



**v0.3.4.3 后台命令窗口静默：** Windows 下启动扫描影片时，ffprobe 媒体探测和 FFmpeg 自动取帧均使用无控制台窗口方式运行，避免每部影片扫描时弹出/闪烁命令行窗口。扫描逻辑本身不变。

**v0.3.4.2 恢复后自动重启：** 从备份成功恢复资料后，终端会先结束当前实例、释放单实例通信通道，再自动拉起新实例载入恢复后的数据库、影片/游戏档案与设置；不再要求手动重新启动。

**v0.3.4.1 游戏档案界面收口：** 游戏右键中的“查看详情 / 编辑游戏”合并为单一“游戏档案”。档案窗口拆成“资料 / 游玩 / 媒体”三个页签：资料直接编辑并保存，游玩只看自动记录的 Session，媒体保留大图 + 横向缩略图胶卷。档案窗口不再重复展示大型封面。原有“备注”在界面中改名为“我的记录”，并新增独立“作品介绍”字段；旧游戏 JSON/数据库会自动兼容迁移。

**v0.3.4 单实例保护：** 同一 Windows 用户下只允许一个本地资源终端实例。再次启动时不会加载第二套设置、数据库、影片/游戏服务或 Session，而是通过 Qt 本地 IPC 通知已运行窗口恢复并置前，然后新进程正常退出；不使用可能残留的 `.lock` 文件。

**v0.3.3.1 UI 稳定性热修复：** 修复窗口缩到较小尺寸后快速切换“影片 / 游戏”时，窗口会短暂被布局撑高再缩回的弹动。切库期间现在同步锁定当前窗口尺寸，切换完成立即恢复可自由缩放；仍不持久化窗口尺寸。

**v0.3.3 第一阶段易用性收尾：** 游戏截图区升级为“主展示区 + 横向缩略图胶卷”的媒体浏览骨架；影片/游戏切换保持本次运行中用户调整后的窗口尺寸；编辑游戏可安全清除终端管理的封面/GIF副本。v0.3.2 的运行中实时计时显示继续保留。

## 主界面

第一阶段已移除旧版左侧分类栏，主界面把空间还给资源墙。

顶部提供：

- **影片 / 游戏** 一级资源库切换。
- 搜索。
- 筛选。
- 排序与升/降序。
- 当前资源领域自己的主要操作。

影片和游戏分别保存自己的排序/常用筛选状态；**搜索文字不会跨启动持久化**。在“设置”中可以选择软件启动后默认进入 **影片** 或 **游戏**。

## 影片库

现有影片能力继续保留：

- PySide6 原生桌面界面，不启动网页服务。
- 多影片库目录，可分别命名和启用/禁用。
- 默认封面墙，可切换列表视图。海报固定显示宽度，高度按原图比例计算，不裁切、不补边、不永久显示文字徽章。
- 搜索编号、标题、演员、系列、厂商、标签和备注。
- 排序：最近添加、编号、标题、发行日期、评分、最后观看、观看次数。
- 海报墙和列表支持 Ctrl / Shift 多选及批量编辑。
- 收藏、观看状态、评分、观看次数、首次/最后播放时间。
- 每次从终端成功发起播放都会留下播放记录。
- 视频文件删除后，永久影片档案不会删除；以后文件重新出现仍可重新关联。
- SQLite 用于快速查询；JSON 用于永久档案和数据库重建。
- 封面集中存放，不要求放进影片目录。
- 封面处理支持完整 DVD Wrap 自动识别 Front，并提供手动裁剪兜底。
- 支持 Windows 默认播放器或自定义 PotPlayer、VLC、mpv、MPC-HC 等播放器。
- ffprobe 可读取时长、分辨率、编码和内嵌字幕信息。

### 推荐影片目录

```text
D:\Movies\
├─ SPSD-62\
│  ├─ SPSD-62.mp4
│  └─ SPSD-62.srt
├─ SPSF-47\
│  └─ SPSF-47.mkv
└─ ...
```

影片正式封面仍使用独立的**集中封面目录**，v0.3.4.x 不会迁移这个目录：

```text
D:\MovieCovers\
├─ SPSD-62.jpg
├─ SPSF-47.jpg
└─ ...
```

## 游戏库 v1

游戏库只管理你**主动加入**的本地游戏。

它不会：

- 扫描 Steam / GOG / Epic 正版库。
- 扫描某个游戏目录并猜哪个 EXE 能启动。
- 替代模拟器自身的游戏管理。
- 管理 Mod、存档、成就或云同步。

### 手动添加游戏

每款游戏由你明确指定：

- 游戏名称、系列、开发商、发行商、发行日期。
- 标签、评分、收藏、备注。
- **启动 EXE**。
- **计时 EXE**。
- 可选启动参数。
- 工作目录（默认启动 EXE 所在目录）。
- 静态封面。
- 可选 GIF 动态预览。
- 可选外部截图目录。

选择启动 EXE 后，计时 EXE 默认与它相同。如果某款游戏通过 Launcher 再打开真正的游戏程序，可以把“计时 EXE”手动指定为真正的游戏进程。

### 安装状态

游戏档案不依赖安装状态存在：

```text
启动 EXE 存在   → 已安装
启动 EXE 不存在 → 未安装 / 仅档案
```

游戏本体删掉或移动后，封面、GIF、标签、评分、备注、总时长和历史 Session 都继续保留。重新安装后只需编辑档案并重新选择 EXE。

## 游戏启动与游玩时长

时长只统计**从本终端发起**的游戏。

流程：

```text
双击游戏封面
   ↓
启动 launch_exe
   ↓
等待 timing_exe 出现
   ↓
创建唯一 GameSession
   ↓
每秒更新计时显示
   ↓
每 30 秒覆盖保存检查点
   ↓
timing_exe 退出
   ↓
精确到秒结算本次 Session
```

规则：

- 从资源管理器或其他启动器直接打开的游戏不会被终端自动接管计时。
- 启动器打开后，只有指定的计时 EXE 真正出现才开始计时；等待最多 5 分钟。
- 同一时间只允许**第一个游戏**取得计时资格。
- 如果正在记录游戏 A 时误点游戏 B，B 仍可正常启动，但会静默不计时，也不会抢占 A。
- 界面每秒更新计时；SQLite/活动状态每 **30 秒**覆盖一个检查点，不会每 30 秒新增一条历史记录。
- 一次实际游玩最终只留下**一条 Session**。
- 正常退出游戏时精确结算到秒。
- 如果终端崩溃、Windows 重启或断电，下次启动会用最后一个检查点恢复；若游戏仍在运行，则继续同一 Session。
- 游戏正在计时时主动关闭终端会先警告；选择仍然退出时会结算到当前秒。第一版不做后台常驻服务。

主界面存在有效 Session 时会显示类似：

```text
正在记录：游戏名称  01:27:43
```

## 游戏封面与 GIF 预览

每款游戏第一版最多拥有：

- 1 张静态封面。
- 1 个 GIF 动态预览。

行为：

- 平时只显示静态封面。
- 鼠标在封面上停留约 **250 ms** 后，有 GIF 时开始循环播放。
- 鼠标移开立即停止并恢复静态封面。
- 同一时间最多播放一个 GIF。
- GIF 损坏时静默回退到静态封面。

游戏封面和 GIF 会复制进终端自己的永久资源目录，因此游戏本体删掉后仍然存在。

第一阶段不加入 MP4/WebM 预览、自动音乐、游戏主题音效等包装功能。

## 游戏截图

终端第一版**只管理截图，不负责截屏**。

每款游戏可以绑定一个外部截图目录：

- 在游戏详情中使用“上方主展示区 + 下方横向缩略图胶卷”。
- 单击缩略图会直接在上方展示原始图片；GIF 会在主展示区播放，切换后停止。
- 打开详情页或点击“刷新”时重新读取。
- 双击缩略图仍可调用系统默认图片查看器打开原图。
- 主展示区直接读取你自己的原始媒体文件；完整原图/GIF不会复制进 cache，也不会被终端删除。
- 缩略图只放在可重建 cache 中。
- 截图目录失效只影响截图区，不影响游戏档案或启动。

## 游戏海报墙操作

- 单击：选中。
- 双击：启动游戏。
- 鼠标悬停约 250 ms：播放已配置 GIF。
- 右键：启动、详情、编辑、收藏、打开游戏目录、打开截图目录、删除游戏档案。

“删除游戏档案”只删除终端中的 JSON、SQLite 记录、Session、封面/GIF 和缩略图缓存，**不会删除游戏 EXE、安装目录、存档或外部截图**。

游戏排序支持：

- 最近添加。
- 游戏名称。
- 发行日期。
- 评分。
- 累计游玩时间。
- 最近游玩。
- 游玩次数。

## 永久档案目录

v0.3.0 开始明确把影片和游戏档案分开：

```text
Data\
├─ library.db
├─ metadata\
│  ├─ movies\
│  │  └─ <movie-uuid>.json
│  └─ games\
│     └─ <game-uuid>.json
├─ game_assets\
│  ├─ covers\
│  └─ previews\
├─ state\
│  └─ active_game_session.json   ← 仅计时中临时存在
├─ cache\
│  ├─ movies\
│  ├─ thumbnails\
│  ├─ generated_covers\
│  └─ games\
│     └─ screenshots\
└─ logs\
```

职责：

- `metadata/movies`：影片永久 JSON 档案。
- `metadata/games`：游戏永久 JSON 档案及已完成 Session。
- `library.db`：运行时索引和查询层；永久档案仍以 JSON 为长期来源。
- `game_assets`：永久游戏封面/GIF。
- `state/active_game_session.json`：唯一活动游戏的临时恢复检查点。
- `cache`：可删除、可重建。

### 从 v0.2.7 自动升级

旧版本的影片档案位于：

```text
metadata\*.json
```

v0.3.0 第一次启动会安全迁移到：

```text
metadata\movies\*.json
```

流程为“读取验证 → 复制 → 再验证 → 成功后才删除旧位置”。如果某个档案迁移失败，旧文件会保留，不会为了升级强行删除。

**现有集中影片封面目录不会被迁移。**

## 备份与恢复

备份与恢复仍只放在 **设置** 页面。

v0.3.0 的选项改名为：

> ☑ **包含视觉资源**

默认勾选时包含：

- `library.db` 一致性快照。
- `metadata/movies` 影片永久档案。
- `metadata/games` 游戏永久档案和已完成游玩 Session。
- `settings.json` 设置快照。
- 集中影片正式封面。
- 游戏封面。
- 游戏 GIF 预览。

明确不包含：

- 影片视频。
- 游戏本体和安装目录。
- 外部截图原图。
- cache。
- logs。
- 正在运行的 `active_game_session.json` 临时状态。

恢复时：

- 数据库与影片/游戏永久档案恢复为备份状态。
- 视觉资源采用合并恢复：备份中同名资源覆盖，当前存在但备份没有的其他资源保留。
- 当前电脑的数据目录、影片集中封面目录、影片库、播放器和 FFmpeg/ffprobe 等机器路径设置不会被旧电脑配置覆盖。
- 游戏档案内部保存的启动 EXE、计时 EXE、截图目录会随游戏档案恢复；路径在当前电脑不存在时只显示“未安装/目录不可用”，不会删除档案。
- v0.3.0 仍可以恢复旧版 v1 备份中的 `data/metadata/*.json` 影片档案。
- 恢复失败会尝试回滚数据库、档案树、设置和被覆盖的视觉资源。

## 设置：启动默认资源库

在 **设置 → 启动默认资源库** 可以选择：

- 影片
- 游戏

默认是“影片”。这个设置决定**每次启动首先进入哪个资源库**，不是“记住上次关闭时在哪一页”。

## 封面处理

影片模式顶部点击 **“封面工具”** 打开封面处理窗口。

推荐：

```text
D:\GigaCoversRaw\    ← 原始完整封面，永久保留
D:\MovieCovers\      ← 裁剪后的 Front
```

处理规则：

- 完整 DVD 封面按左 Back / 中 Spine / 右 Front 的结构处理。
- Spine 不依赖固定颜色。
- 原始封面永不修改。
- 默认不覆盖正式封面。
- 不可靠宽图标记“需人工复核”。
- 双击/右键扫描结果可进入手动裁剪，拖动 Front 起点后实时预览。
- 原始目录和正式输出目录不能相同。

## Windows 安装与升级

需要：

- Python 3.11 或更新版本（64 位推荐）。
- PySide6。
- Pillow。
- FFmpeg / ffprobe（推荐；影片媒体信息使用）。

首次安装可双击：

```text
setup_windows.bat
```

日常静默启动：

```text
run_windows.vbs
```

兼容保留旧的：

```text
启动影片管理器.vbs
```

两者都使用 `pythonw.exe`，不会保留 CMD 黑窗口。排错时使用：

```text
run_windows_debug.bat
```

### 从 v0.2.7 使用补丁升级

v0.3.0 **没有新增 Python 依赖**。关闭软件后，把补丁内容复制到原程序根目录并覆盖即可，通常不需要重新运行 `setup_windows.bat`。

应用数据、集中封面、影片和游戏本体都应放在程序安装目录之外；升级程序目录不会替代这些永久数据。

## FFmpeg / ffprobe

如果已加入 Windows `PATH`，默认设置即可；否则可在设置中分别选择 `ffmpeg.exe` 和 `ffprobe.exe`。

ffprobe 不可用时影片仍可入库和管理，只是时长、分辨率、编码和内嵌字幕信息可能为空。

## 开发测试

安装测试依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
```

运行：

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

当前构建环境如果没有 PySide6，Qt UI 测试会跳过；核心数据、迁移、计时、备份、游戏资产和源代码回归测试仍可运行。

## 第一阶段仍不包含

- 在线元数据刮削。
- 内置影片播放器。
- 转码。
- Web 服务或远程访问。
- 多设备同步。
- 实时目录监听。
- Steam/GOG/Epic 账号或正版库聚合。
- 模拟器/ROM 前端。
- 游戏成就、Mod、云存档管理。
- 软件主动截图 / 全局手柄截图。
- 游戏视频预览和音乐主题。
- 音乐与漫画资源领域。

这些内容不会为了“本地资源终端”这个名字在 v0.3.0 中提前抽象或实现。
