# v0.3.3 第一阶段易用性收尾设计

日期：2026-08-17
基线：v0.3.2

## 范围

本版本只实现三项已经确认的改动，不包含尚未确认的“游戏详情/编辑合并”，也不包含单实例、在线资料搜索或第二阶段视觉包装。

## 1. 截图浏览器骨架

现有游戏详情中的截图网格升级为媒体浏览器骨架：

- 上方为单一主展示区。
- 下方为横向缩略图胶卷，可水平滚动。
- 单击缩略图后，上方立即展示对应媒体。
- 普通图片直接从外部截图原图读取并按主展示区等比例缩放；不复制完整原图到 cache。
- GIF 可作为媒体项；被选中时在主展示区播放，切换到其他媒体时停止。
- cache 仍只保存缩略图。
- 双击缩略图继续允许调用系统默认程序打开原始文件。
- 截图目录只在打开详情或手动刷新时读取，不增加 watcher、Overlay、截图热键或游戏运行时监控。
- 目录不可用时只显示状态提示，不影响游戏档案与启动。

本版本只做功能骨架，不加入 GOG/2077 式玻璃、Hero 背景、转场或赛博动效。

## 2. 运行期窗口尺寸保持

- 主窗口默认启动尺寸继续为 1320 × 840。
- 用户在本次运行中手动调整窗口尺寸后，影片/游戏库切换必须保持用户当前尺寸。
- 切换库不得因为控件显示/隐藏或 stacked widget 页面变化把高度恢复为默认值。
- 不把窗口 geometry/size 写入 settings。
- 完全退出程序后再次启动，仍使用默认 1320 × 840。
- 本次只保持 size，不新增窗口位置持久化。

实现方式：切换资源库前捕获当前 `QSize`，完成控件切换与刷新后在当前事件循环中恢复该尺寸，避免 Qt 布局更新覆盖用户尺寸。

## 3. 游戏封面/GIF清除

编辑游戏窗口的“静态封面”和“GIF 动态预览”各增加一个“清除”按钮。

- 对已有受管理资产，点击清除后 UI 立即显示为空。
- 保存编辑后：
  - 从游戏 metadata 中清除 `cover_path` 或 `preview_gif_path`；
  - 删除终端 `game_assets` 中该游戏对应的受管理副本；
  - 绝不删除用户最初导入的源图片/GIF。
- 如果用户先点“清除”又重新选择新文件，则最终保存新文件，不执行清除结果。
- 添加新游戏时没有已有受管理资产，“清除”仅清空尚未选择的源文件状态，不产生磁盘删除。
- 删除受管理文件仍通过 `GameAssetService` 负责，UI 不直接删除任意路径，以维持所有权边界。

## 测试

- 截图服务继续验证缩略图缓存只位于 cache。
- UI 源码/Qt 可用环境测试媒体浏览器包含主展示区、横向胶卷、图片/GIF切换路径。
- 主窗口库切换前后 size 保持，且没有 settings 持久化 geometry。
- GameEditResult 能表达 remove_cover/remove_preview。
- `GameCatalogService.update_game` 删除受管理资产且保留源文件。
- 清除后再选新资源时以新资源为最终结果。
- 全量现有影片和游戏测试继续通过。
