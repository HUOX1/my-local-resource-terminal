# 本地资源终端：游戏库 v1 设计规格

日期：2026-08-17  
基线：本地影片管理器 v0.2.7  
阶段：第一阶段功能扩展（第二阶段视觉包装之前）

## 1. 产品定位与范围

当前软件从“本地影片管理器”扩展为“本地资源终端”，第一阶段新增第二个一等资源领域：**游戏**。

架构采用：**平行领域模块 + 共享应用外壳**。

现有影片领域尽量保持稳定；游戏新增独立模型、数据表、仓储、服务与 UI。两者共享主窗口、顶部资源切换、搜索/排序/筛选、设置、备份恢复与未来主题系统。

本次只实现影片 + 游戏。音乐、漫画不据此提前设计通用 `Resource` 模型。

明确不做：Steam/GOG/Epic 库同步；账号、成就、云存档、商店抓取；模拟器/ROM 前端；Mod/补丁/存档管理；自动扫描或猜测 EXE；软件自身全局截图；多游戏并发计时；多启动方案；MP4/WebM 预览；详情页音乐/视频背景等第二阶段包装功能。

## 2. 游戏档案与导入

游戏完全由用户手动添加，不扫描、不猜测。每个游戏拥有永久 UUID，与安装路径无关；游戏本体删除或移动后，档案继续保留。

`GameRecord` 建议字段：

- `uuid`
- `title`
- `series`
- `developer`
- `publisher`
- `release_date`
- `tags`
- `rating`
- `favorite`
- `notes`
- `added_at`
- `launch_exe`
- `launch_args`
- `working_directory`
- `timing_exe`
- `cover_path`
- `preview_gif_path`
- `screenshot_directory`
- `total_play_seconds`
- `play_count`
- `first_played_at`
- `last_played_at`

`installed` 不持久化：`launch_exe` 存在即“已安装”，否则“未安装”。未安装不影响封面、GIF、截图目录引用、评分、标签、备注和游玩历史。

## 3. 启动配置

第一版每款游戏只有一个启动配置：

- 启动 EXE
- 可选启动参数
- 工作目录
- 计时 EXE

选择启动 EXE 后，工作目录默认设为 EXE 所在目录，计时 EXE 默认等于启动 EXE。若游戏通过 Launcher 启动真正游戏进程，由用户手动把计时 EXE 指向真正游戏 EXE。

不自动枚举目录中的其他 EXE。

## 4. 启动与计时状态机

终端同一时刻只维护一个具有计时资格的活动游戏：

```text
空闲 → 启动请求 → 等待计时进程 → 正在计时 → 结算 → 空闲
```

### 4.1 启动

双击封面：

1. 检查 `launch_exe`。
2. 路径失效则提示，不建立 Session。
3. 成功启动后进入“等待计时进程”。
4. 此时不计时。

### 4.2 等待计时进程

约每秒检查用户指定的 `timing_exe`，实现时尽量按完整可执行文件路径核对。

真正的计时进程出现时才：

- 创建 `GameSession`
- 写 `started_at`
- 开始秒级计时显示
- `play_count + 1`
- 首次游玩时写 `first_played_at`
- 创建活动 Session 恢复状态

点击启动到计时进程出现之间的时间不算游玩时间。

等待上限 5 分钟；超时则放弃，不建立游玩记录。

### 4.3 唯一活动游戏

游戏 A 已取得计时资格后，从终端再启动 B：

- B 正常启动
- B 静默不计时
- B 不建 Session
- B 不抢占 A
- A 继续计时

A 结算后，下一款游戏才可取得计时资格。

### 4.4 外部启动不计时

只有由本终端发起的启动流程可以建立 Session。资源管理器、快捷方式或其他启动器直接打开的游戏不接管、不补计时、不提示。

终端总时长定义为：**通过本终端启动，并成功进入计时状态的实际游玩时间。**

## 5. GameSession 与可靠计时

一次有效游玩对应一条 Session。

建议字段：

- `id`
- `game_uuid`
- `started_at`
- `ended_at`
- `duration_seconds`
- `last_checkpoint_at`
- `status`

`status` 至少包含：`active`、`completed`、`recovered`。

### 5.1 每秒显示，30 秒检查点

- UI 每秒更新一次。
- 内存保持秒级精度。
- 每 30 秒覆盖当前 Session 检查点。
- 检查点不是新增历史记录。
- 正常退出时精确结算到秒。

一次 5 小时游玩仍只有一条 Session。

### 5.2 正常退出

计时进程消失后：记录 `ended_at` → 计算 `duration_seconds` → 标记 `completed` → 更新总时长/最近游玩 → 写永久游戏 JSON → 更新 SQLite → 清理活动状态 → 回到空闲。

### 5.3 活动 Session 恢复状态

使用单一临时文件：

```text
state/active_game_session.json
```

每 30 秒覆盖，不产生历史文件。

### 5.4 异常恢复

启动时发现未结算活动 Session：

- 对应计时进程仍在：继续同一 Session。
- 对应计时进程不在：按最后可信检查点结算，标记 `recovered`。

异常时最多损失不足一个 30 秒检查点周期的时长。

### 5.5 主动关闭终端

有活动 Session 时关闭应用，提示“关闭终端将停止本次时长记录”。可取消或仍然退出。

选择仍然退出时立即精确结算到当前秒；游戏之后继续运行也不再计时。第一版不做后台服务或托盘计时代理。

## 6. 截图管理

第一版只管理截图，不负责截屏。

每款游戏绑定一个外部截图目录：

- 原图不复制
- 不进入普通备份
- 打开详情页或手动刷新时重新读取
- 不持续监听文件系统
- 详情页完整缩略图网格
- 默认按时间排序
- 双击调用系统默认图片查看器
- 目录失效只影响截图区，可重新选择
- 只缓存可重建缩略图
- 不建立永久逐张截图数据库

## 7. 封面与 GIF 预览

游戏封面与 GIF 复制到应用自己的游戏资产目录，属于永久档案资产。每款游戏第一版最多 1 张静态封面 + 1 个 GIF。

海报墙规则：

- 默认静态封面
- 悬停约 250 ms 后播放 GIF
- 移出立即停止并恢复静态封面
- 同时最多 1 个 GIF 播放
- 快速扫过不连续触发多个 GIF
- GIF 损坏则静默回退静态封面
- 不自动裁剪，按封面区域等比例显示
- GIF 不进入截图体系
- 不支持视频预览或音乐

## 8. 主界面重构

第一阶段删除现有左侧分类栏，不保留空白占位，海报墙使用释放出来的空间。

顶部结构：

```text
[影片] [游戏]   搜索   筛选   排序   升/降序   当前模块主要操作
```

`影片 / 游戏` 是一级资源库切换。

原左侧分类改为顶部轻量筛选：

影片至少有：全部、收藏、已观看、未观看、标签。  
游戏至少有：全部、收藏、已安装、未安装、最近游玩、标签。

切换影片/游戏时，搜索框清空，避免跨领域误筛；搜索文本不持久化。

第二阶段可以重新引入左侧或其他“展示舱”区域（3D 模型、GIF 角色、静态装饰、电子宠物等），但其隐藏、关闭或损坏后，全部核心功能必须仍可使用。第一阶段不实现展示舱。

## 9. 游戏海报墙交互

游戏卡片继续以封面识别为主，不永久堆叠游戏名、厂商、评分等文字。

- 单击：选中
- 双击：启动
- 右键：管理
- 悬停约 250 ms：GIF 预览

未安装只使用低干扰状态标识。

右键菜单建议：启动游戏、查看详情、编辑游戏、收藏/取消收藏、标签、打开游戏目录、打开截图目录、删除游戏档案。

不提供删除游戏文件或卸载游戏。

## 10. 添加 / 编辑游戏

独立对话框。

资料区：名称（必填）、系列、开发商、发行商、发行日期、标签，以及评分/收藏/备注。  
启动区：启动 EXE（必填）、计时 EXE（默认同启动 EXE）、可选参数、工作目录。  
资源区：静态封面、GIF、截图目录。

所有 EXE 均由用户手动选择。

## 11. 游戏详情页

包含四块：

1. 游戏身份：封面、游戏名、系列、开发商/发行商、发行日期、收藏、评分、启动按钮。
2. 档案与时长：累计时长（显示到秒）、游玩次数、首次/最近游玩、安装状态、启动文件、计时进程。
3. 游玩历史：每个已完成 Session 一行；恢复条目轻量标记“已恢复”；30 秒检查点不显示。
4. 截图：完整网格、刷新、打开目录、双击原图、目录失效时重新选择。

## 12. 当前计时状态显示

仅存在活动 Session 时，在主界面轻量状态区显示：

```text
正在记录：<游戏名>  01:27:43
```

每秒更新。没有活动 Session 时不占显著空间。误开第二个游戏时仍只显示第一个活动游戏。

## 13. 排序与浏览状态

游戏排序支持：最近添加、游戏名称、发行日期、评分、累计游玩时间、最近游玩、游玩次数；支持升/降序。

影片与游戏分别保存自己的排序/筛选状态。搜索文本不持久化。

## 14. 设置

新增：

```text
设置 → 常规 → 启动默认资源库 → 影片 / 游戏
```

默认“影片”。这是默认首页，不是记住上次退出位置；每次启动按此设置进入对应资源库。

## 15. 数据目录

```text
data/
├─ library.db
├─ settings.json
├─ metadata/
│  ├─ movies/
│  │  └─ *.json
│  └─ games/
│     └─ *.json
├─ game_assets/
│  ├─ covers/
│  └─ previews/
├─ state/
│  └─ active_game_session.json
├─ cache/
│  ├─ movies/
│  └─ games/
│     └─ screenshots/
└─ logs/
```

现有影片正式封面继续使用用户当前配置的中央封面目录，本次不强制迁移。

## 16. SQLite 结构与迁移

保留影片现有表；新增 `games`、`game_sessions`，不混入统一 `resources` 表。

数据库增加显式 `schema_version` 迁移机制。结构升级使用事务，失败回滚，不以半升级状态继续业务写入。

## 17. JSON 与 SQLite 职责

延续现有原则：JSON 是永久档案源；SQLite 用于快速索引、查询、排序和运行期状态。

每款游戏使用：

```text
metadata/games/<game-uuid>.json
```

游戏 JSON 保存资料、启动配置、永久视觉资源引用、截图目录引用、汇总时长以及**已完成** Session 历史。

活动 Session 不每 30 秒重写完整游戏 JSON；只更新 SQLite 当前 Session 和 `state/active_game_session.json`。结算后才写永久游戏 JSON。

`library.db` 丢失时，应可从影片 JSON 和游戏 JSON 重建永久档案与已完成历史。

## 18. 永久 JSON 原子写入

影片和游戏永久 JSON 统一采用：写临时文件 → 验证 JSON 可读 → 原子替换正式文件。

这是 metadata 迁移涉及到的可靠性补强，不扩大成无关重构。

## 19. 影片 metadata 安全迁移

旧：`metadata/*.json`  
新：`metadata/movies/*.json`

升级时逐个：读取旧 JSON → 验证合法影片档案 → 复制到新目录 → 再读验证 → 成功后才清理旧文件。

任何一步失败都保留旧文件并记录错误。迁移必须幂等；重复启动不会产生重复档案，也不得改变影片 UUID、`added_at`、观看历史等永久信息。

迁移完成后影片永久档案只从 `metadata/movies/` 读取。

## 20. 删除游戏档案

只删除：游戏 JSON、SQLite 游戏记录、该游戏 Session、游戏封面、GIF、截图缩略图缓存。

绝不删除：游戏 EXE、安装目录、存档、外部截图目录、截图原图。

确认框必须明确说明此边界。

## 21. 备份

现有备份扩展到游戏。

默认备份包括：一致性 `library.db` 快照、`metadata/movies/`、`metadata/games/`、`settings.json`，以及启用视觉资源备份时的影片封面、游戏封面、游戏 GIF。已完成 Session 和汇总时长随数据库/JSON进入备份。

设置文案由“包含封面”改为“**包含视觉资源**”，默认勾选。

不备份：影片本体、游戏本体、游戏安装目录、外部截图原图、cache、logs、`state/active_game_session.json`。

若备份时存在活动 Session，可先刷新一次检查点；普通备份只承诺已完成永久历史，不把正在运行的临时 Session 作为可恢复业务状态写入备份。

## 22. 恢复

恢复继续使用当前机器配置的数据目录和影片封面目录，不用旧备份的应用数据根路径覆盖当前机器路径。

游戏档案中的启动 EXE、计时 EXE、截图目录属于游戏自身引用，随档案恢复：路径有效则正常使用；启动 EXE 失效则显示未安装；截图目录失效则仅显示不可用。路径失效绝不删除档案。

游戏封面/GIF 采用现有封面恢复的合并思想：备份中的同名资源覆盖当前目标；当前存在但备份中没有的其他视觉资源不做无关删除。失败延续现有 rollback 思路。

## 23. 错误处理

- 启动失败：不建 Session、不增加次数、不修改首次/最近游玩，显示错误。
- 计时进程 5 分钟未出现：放弃等待，不建 Session。
- GIF 错误：回退静态封面，不影响海报墙。
- 截图目录错误：只影响截图区域。
- metadata 迁移错误：保留旧影片 JSON。
- 数据库升级错误：事务回滚。

## 25. 成功标准

1. 手动建立和长期保存游戏档案。
2. 从终端启动本地游戏。
3. 可靠记录由终端发起的唯一活动游戏的真实游玩时长。
4. Session 历史具备 30 秒异常恢复能力。
5. 每款游戏可绑定永久封面和 GIF 悬停预览。
6. 可浏览外部截图目录完整网格。
7. 游戏删除/移动不丢永久档案。
8. 影片和游戏 metadata 明确分开。
9. 备份恢复覆盖游戏永久数据和视觉资产。
10. 主界面移除左侧功能栏，影片/游戏改为顶部一级切换。
11. 不为未来音乐/漫画提前建立万能资源系统。
12. 第二阶段视觉包装在这些功能稳定后再开始。

## 26. 最终决策覆盖早期讨论

- 资源库切换：早期曾选择左侧；最终改为顶部 `[影片] [游戏]`。
- 左侧栏：第一阶段完全移除；第二阶段若重新出现，只能是非必要装饰展示舱。
- 截图：只管理，不由终端截屏。
- EXE：完全手动选择，不扫描。
- 计时：只统计本终端发起的第一个/唯一活动游戏；后续误开的游戏静默不计时。
- 检查点：每秒显示、每 30 秒覆盖保存、正常退出精确到秒。
- “本地资源终端”是产品定位，不代表现在建立通用 `Resource` 数据结构。
