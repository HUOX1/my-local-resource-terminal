# 本地影片管理器设计规格

日期：2026-08-16

## 1. 目标

构建一个面向 Windows 的纯本地桌面影片管理器。它不提供账户系统、远程访问、转码服务或内置流媒体服务器，只负责本地影片的扫描、整理、浏览、搜索、编辑元数据、封面管理与外部播放器调用。

核心体验：

- 启动后直接看到影片封面墙。
- 可以切换为信息列表视图。
- 支持多个影片库根目录，并给每个根目录自定义名称。
- 影片档案与实际视频文件彻底解耦：视频可以被删除、移动或暂时离线，但封面、元数据、评分、收藏与观看痕迹持续保留，除非用户在软件中主动删除档案。
- 影片资料同时写入 SQLite 与集中式 `metadata` 目录中的 JSON 文件，便于快速查询、备份和数据库重建。
- 封面集中存放在一个独立的“封面目录”中，默认使用与影片 `cover_key` 同名的图片文件，便于批量整理和替换。
- 封面是第一优先级视觉元素。
- 播放交给 Windows 默认播放器或用户指定的播放器；仅当影片当前存在本地文件时可播放。

## 2. 技术栈

- Python 3.11+
- PySide6 Widgets
- SQLite
- JSON
- ffprobe（来自 FFmpeg）

第一版不使用 QML，不启动本地 Web 服务，不依赖浏览器。

## 3. 影片目录与档案目录约定

第一版以“一部影片一个文件夹”为视频文件的推荐结构，但影片档案不再存入该文件夹：

```text
D:\Movies\SPSD-62\
├─ SPSD-62.mp4
└─ SPSD-62.srt

D:\MovieManagerData\
├─ library.db
├─ metadata\
│  ├─ <uuid>.json
│  └─ ...
└─ cache\
   ├─ thumbnails\
   └─ generated_covers\

D:\MovieCovers\
├─ SPSD-62.jpg
├─ SPSF-47.jpg
└─ ...
```

要求：

- 视频文件夹存在时，一个影片文件夹内必须至少存在一个受支持的视频文件。
- 目录名通常就是影片编号，但程序不能依赖这一点；编号优先从集中元数据读取，其次从主视频文件名或目录名推断。
- 影片目录内不要求存放封面或元数据文件。
- 每部影片拥有稳定 UUID。集中式元数据文件以 UUID 命名，因此视频改名、移动或删除不会导致档案身份丢失。
- 每部影片额外保存稳定的 `cover_key`。首次发现时默认取主视频文件名去掉扩展名；即使视频后来离线，程序仍可继续通过 `cover_key` 显示集中封面。
- 一个目录内若有多个视频文件，优先按文件名与目录名匹配；若无法唯一判断，则选择体积最大的受支持视频作为主影片，并在界面中允许用户修正。
- 第一版支持常见视频扩展名：`.mp4`、`.mkv`、`.avi`、`.mov`、`.wmv`、`.m4v`、`.ts`、`.webm`。
- 第一版支持外置字幕发现：`.srt`、`.ass`、`.ssa`、`.vtt`。

## 4. 多影片库

支持配置多个根目录，例如：

```text
D:\GIGA\
E:\Archive\
F:\New\
```

每个根目录包含：

- 显示名称，例如“主收藏”“旧收藏”“新片”。
- 本地路径。
- 启用/禁用状态。

所有影片默认汇总到“全部影片”，同时可以按影片库筛选。

## 5. 扫描与同步

### 5.1 启动扫描

程序启动时执行一次快速扫描：

1. 读取已配置的影片库根目录。
2. 递归遍历根目录；任一目录只要直接包含受支持的视频文件，就视为影片目录候选。识别为影片目录后，不再把它的子目录当作独立影片目录扫描，避免花絮或附加素材目录被误判。
3. 根据主视频路径、历史关联信息、编号和 `cover_key` 尝试匹配既有档案；没有匹配时创建新的稳定 UUID 与集中式元数据文件。
4. 发现视频和字幕，并到独立封面目录中按 `cover_key` 匹配封面。
5. 使用 ffprobe 读取主影片媒体信息。
6. 将当前存在的视频标记为 `available` 并更新其文件路径；对于数据库中曾存在但本次扫描未发现的视频，仅标记为 `offline`，保留档案和观看历史。
7. 将结果同步到 SQLite 与必要的集中式 JSON 元数据。
8. 更新 UI。

### 5.2 手动扫描

主界面提供“重新扫描”按钮，可重新执行完整扫描。

### 5.3 第一版不做

- 不做后台实时文件监听。
- 不在文件变动时自动弹出提示。
- 不做远程文件系统同步。

## 6. 元数据字段

第一版每部影片包含以下字段：

- 编号 `code`
- 标题 `title`
- 演员 `actors`
- 系列 `series`
- 厂商 `studio`
- 发行日期 `release_date`
- 标签 `tags`
- 评分 `rating`
- 观看状态 `watched`
- 观看次数 `play_count`
- 收藏 `favorite`
- 本地可用状态 `availability_status`（`available` / `offline`，自动计算）
- 字幕状态 `subtitle_status`（自动计算，只读；离线时保留最后一次已知状态）
- 备注 `notes`
- 文件路径 `video_path`
- 封面路径 `cover_path`
- 所属影片库 `library_id`
- 媒体时长 `duration`
- 分辨率 `width` / `height`
- 视频编码 `video_codec`
- 音频编码 `audio_codec`
- 文件大小 `file_size`
- 最近扫描时间 `last_scanned_at`
- 首次观看时间 `first_watched_at`
- 最后观看时间 `last_watched_at`
- 播放记录 `play_history`（记录每次从管理器发起播放的时间；不宣称代表看完或播放进度）
- 稳定档案 ID `uuid`
- 封面匹配键 `cover_key`

### 6.1 演员与标签

- SQLite 内采用关系表存储，便于筛选与去重。
- 集中式元数据 JSON 中使用字符串数组。

## 7. 双存储策略

### 7.1 集中式元数据 JSON

影片元数据不再放入影片目录，而是统一保存在可配置的应用数据目录中：

```text
D:\MovieManagerData\
├─ library.db
├─ metadata\
│  ├─ 3f2d...a1.json
│  ├─ 8b76...c9.json
│  └─ ...
└─ cache\
```

每个 JSON 文件以稳定 UUID 命名。示例：

```json
{
  "schema_version": 1,
  "uuid": "3f2d5be0-0000-0000-0000-000000000000",
  "cover_key": "SPSD-62",
  "code": "SPSD-62",
  "title": "",
  "actors": [],
  "series": "",
  "studio": "",
  "release_date": "",
  "tags": [],
  "rating": 0,
  "watched": false,
  "play_count": 0,
  "favorite": false,
  "notes": "",
  "first_watched_at": null,
  "last_watched_at": null,
  "play_history": []
}
```

约束：

- JSON 保存用户维护的数据、稳定 UUID、`cover_key` 与观看痕迹，包括每次从管理器发起播放的时间记录。
- JSON 不依赖视频当前是否存在；视频删除后 JSON 继续保留。
- 视频路径、文件大小、媒体编码等可重建信息主要由 SQLite 保存，不作为 JSON 的永久身份依据。
- `availability_status` 由扫描结果计算，不写入 JSON。
- 用户在界面中修改永久元数据或观看状态时，同时更新 JSON 和 SQLite。
- 只有用户执行“删除影片档案”时，才删除对应 JSON；删除视频文件本身绝不触发档案删除。

### 7.2 SQLite

SQLite 是运行时索引、文件关联与查询数据库。

用途：

- 快速搜索、排序与筛选。
- 影片库汇总。
- 演员、系列、厂商、标签筛选。
- 当前视频路径与在线/离线状态。
- 媒体技术信息与字幕状态。
- 观看状态、观看次数、收藏与时间信息查询。
- 保存逐次播放事件，用于快速查询基础观看历史；同一事件同时写入集中式 JSON，确保数据库重建后仍可恢复。

数据库被删除时，可以通过集中式 `metadata` 目录重建所有永久档案；之后重新扫描影片库即可恢复当前视频路径和技术信息。

### 7.3 永久档案原则

- 扫描只负责发现、关联和更新文件状态，不自动删除影片档案。
- 视频消失、硬盘未连接或影片库路径暂时不可访问时，档案继续存在。
- “全部影片”默认包含在线与离线档案。
- 用户可以筛选“本地可播放”与“仅档案”。
- 永久删除必须由用户显式执行，并进行确认。

## 8. 封面管理

封面是第一版的重点功能，并采用独立集中目录管理。

### 8.1 独立封面目录

设置页允许用户指定一个封面根目录，例如：

```text
D:\MovieCovers\
├─ SPSD-62.jpg
├─ SPSF-47.jpg
├─ ABC-123.png
└─ ...
```

匹配规则：

1. 每部影片使用持久化的 `cover_key` 匹配封面。首次从本地视频创建档案时，默认取主视频文件名去掉扩展名作为 `cover_key`，例如 `SPSD-62.mp4` → `SPSD-62`。视频离线后 `cover_key` 不变。
2. 在封面目录中查找同名图片：`SPSD-62.jpg`、`SPSD-62.jpeg`、`SPSD-62.png`、`SPSD-62.webp`。
3. 若同名图片存在多个格式，按 `jpg > jpeg > png > webp` 的固定顺序选择，保证结果稳定。
4. 文件名匹配大小写不敏感，以符合 Windows 使用习惯。
5. 若多个档案具有相同 `cover_key`，则默认共享同一张集中封面。

这样用户可以完全脱离影片目录集中维护封面。首次建档时通常只需确保“图片名 = 主视频文件名（不含扩展名）”；建档后则以持久化的 `cover_key` 为准。

### 8.2 封面优先级

封面获取顺序：

1. 独立封面目录中的同名图片。
2. 自动从影片截取的临时封面。
3. 程序内置占位图。

第一版不再自动读取影片目录中的 `cover.jpg` / `poster.jpg`，避免两套封面来源造成冲突。未来如有需要，可增加兼容开关。

### 8.3 自动截帧

当集中封面目录中没有匹配图片时：

- 可调用 FFmpeg 从主影片中抽取一帧作为临时封面。
- 默认截取影片时长约 10% 的位置；若失败则尝试固定偏移。
- 临时封面只放在应用缓存目录，不写回影片目录，也不自动写入集中封面目录。
- UI 明确标记“临时封面”，方便之后集中补图。

### 8.4 手动更换封面

详情页提供“更换封面”：

- 用户选择本地图片后，程序将其复制或转换到独立封面目录。
- 目标文件名自动使用当前档案的 `cover_key`，例如 `SPSD-62.jpg`；因此影片离线时也能更换封面。
- 若目标已存在，覆盖前需要确认。
- 替换完成后立即刷新封面缓存和 UI。

### 8.5 第一版图片范围

- UI 只展示一张主封面。
- 数据结构预留未来“图片集/剧照”扩展能力，但第一版不显示图片集界面。

## 14. 播放器策略

### 14.1 系统默认播放器

使用 Windows 系统关联打开主视频文件。

### 14.2 指定播放器

若指定播放器路径失效，则提示并允许回退系统默认播放器。

## 15. 设置页

第一版设置包含：

- 影片库管理：添加、删除、重命名、启用/禁用根目录。
- 应用数据目录：集中保存 `library.db`、`metadata` 与缓存。
- 封面目录：选择一个独立的集中封面路径，并显示可用/不可用状态。
- 播放方式：系统默认 / 指定播放器。
- 指定播放器路径。
- ffprobe / FFmpeg 路径检测。
- “关联本地文件”入口，用于给离线档案重新指定视频。
- 启动时自动扫描开关，默认开启。

## 16. ffprobe 使用

扫描时读取：

- 时长。
- 视频宽高。
- 视频编码。
- 音频编码。
- 内嵌字幕轨数量。

字幕状态由外置字幕和内嵌字幕共同判断。

ffprobe 不可用时：

- 影片仍可进入媒体库。
- 技术信息留空。
- UI 显示一次非阻塞提示。
- 不影响手动元数据管理与播放。

## 17. 视频离线、重新关联与档案删除

扫描发现某部已知影片的视频文件不再存在时：

- 只将 `availability_status` 更新为 `offline`。
- 保留最后一次已知的 `video_path` 供追溯，但以 `availability_status = offline` 禁止播放；同时保留最后一次已知的媒体技术信息供展示。
- 封面、元数据、评分、收藏、备注、观看状态、观看次数与观看历史全部保留。
- “全部影片”仍显示该影片，并明确标记“仅档案 / 当前无本地视频”。

当以后再次扫描到影片文件时，程序按以下线索尝试重新关联：

1. 已知历史路径或文件指纹线索。
2. `cover_key` / 主视频文件名。
3. 影片编号 `code`。
4. 用户手动选择“关联本地文件”。

若自动匹配存在歧义，不自动覆盖，交给用户确认。

稳定 UUID 只属于影片档案，不依赖视频目录。视频文件移动、改名、删除或恢复，都不会改变 UUID。

真正删除档案只能通过详情页或维护操作中的“删除影片档案”：

- 删除对应 SQLite 永久记录与关系数据。
- 删除对应集中式 metadata JSON。
- 默认不删除集中封面图片和视频文件，避免误删；未来可增加可选复选项。
- 删除前必须确认。

## 18. 错误处理

需处理：

- 影片库路径不存在或硬盘未连接。
- 文件没有访问权限。
- 集中式元数据 JSON 语法损坏。
- ffprobe 不存在或执行失败。
- 封面图片损坏。
- 指定播放器路径无效。
- SQLite 写入失败。

原则：

- 单个影片错误不能阻塞整个影片库扫描。
- 扫描结束后给出简短摘要，例如“新增 12、更新 4、缺失 1、错误 2”。
- 错误日志写入应用日志文件，UI 只展示必要信息。

## 19. 性能原则

针对几千部影片仍应可用。

- 封面缩略图异步加载。
- 原始大图不直接塞入 SQLite。
- 生成并缓存适合封面墙的缩略图。
- SQLite 查询分页或按需加载。
- 扫描工作放入后台线程，避免冻结 UI。
- UI 更新通过 Qt 信号槽回到主线程。

## 20. 模块边界

建议代码结构：

职责要求：

- UI 不直接操作 SQLite。
- 扫描器不直接操作界面控件。
- `metadata_service` 负责集中式 JSON 的读写、UUID 档案与版本兼容。
- `movie_repository` 负责 SQLite 查询、文件关联、在线/离线状态与观看事件持久化。
- `cover_service` 负责集中封面目录的同名匹配、缓存、截帧与替换。
- `player_service` 负责播放器调用。

## 21. 第一版明确不做的功能

- 网站自动刮削。
- GIGA 专用抓取器。
- 在线元数据服务。
- 账户或用户权限。
- Web 界面。
- 远程访问。
- 内置视频播放器。
- 视频转码。
- 多设备同步。
- 实时目录监听。
- 图片集 UI。
- 批量元数据编辑。

这些功能未来可以增量加入，但不得阻塞第一版。

## 22. 第一版完成标准

满足以下条件即视为 MVP 完成：

1. Windows 上可以启动 PySide6 桌面程序。
2. 可以配置至少三个影片库根目录。
3. 启动自动扫描，并能手动重新扫描。
4. 能识别“一影片一文件夹”的主影片与字幕；新发现影片建立稳定 UUID 与集中式元数据 JSON，并通过持久化 `cover_key` 从独立封面目录匹配封面。
5. 能通过 ffprobe 获取基础媒体信息。
6. 默认显示封面墙，并能切换到列表视图。
7. 能按编号、标题、演员、系列、厂商、标签搜索。
8. 能按影片库、收藏、观看状态、字幕状态和本地可用状态筛选。
9. 能打开影片详情并编辑所有用户维护字段；字幕状态和媒体技术信息作为只读自动信息显示。
10. 编辑后 SQLite 与集中式元数据 JSON 同步更新；播放操作能累计观看次数并记录首次/最后观看时间及逐次播放事件，数据库重建后这些观看痕迹仍可恢复。
11. 能手动更换封面并写入独立封面目录；无匹配封面时可以产生临时截帧。
12. 能调用系统默认播放器或用户指定播放器。
13. 删除视频文件后档案、封面与观看痕迹仍保留并显示为离线；数据库删除后，可以通过集中式 `metadata` 目录重建永久档案，再通过扫描恢复本地文件关联。
14. 离线档案可以手动重新关联本地视频；只有用户明确执行“删除影片档案”才永久删除档案。
15. 单个损坏文件不会导致扫描流程整体失败。

## 23. 后续扩展方向

按优先级预留：

1. GIGA 网站图片/元数据半自动导入。
2. 从剪贴板或 URL 快速设置封面。
3. 多图片/剧照管理。
4. 批量编辑标签和观看状态。
5. 更强的高级筛选与保存筛选条件。
6. 自定义播放器启动参数。
7. 文件整理/重命名辅助，但默认不主动移动影片文件。
