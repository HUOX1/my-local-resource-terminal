# 游戏档案内容页设计（v0.4.1.8）

## 目标
把“游戏档案”从模态对话框升级为占据主窗口内容区的独立页面。保留左侧主轴和软件标题栏；档案页左上角使用 `←` 返回游戏海报墙。

## 明确不做
- 不改影片档案；影片以后独立设计。
- 不使用视频，也不引入视频字段、播放器或视频缓存。
- 不重复放大游戏封面；档案 Hero 不以封面作为回退资源。
- 不重新尝试 Windows 外窗玻璃、透明圆角或 DWM 模糊。
- 不改变游戏启动、计时、永久 JSON 档案、SQLite 可重建索引、备份/恢复的基本规则。

## 页面骨架
档案页是 `QWidget`，嵌入主内容区的堆叠页，与游戏海报墙在同一个主窗口内容区域切换。

从上到下：
1. 左上角 `←` 返回按钮。
2. Hero 媒体区：横向展示专属图片/GIF；GIF 自动静音概念不适用，因此只循环动画，不显示播放器控件。
3. Hero 信息层：游戏标题、累计游玩时间、评分、安装状态、启动游戏主按钮。
4. 内容区：作品介绍、我的记录、截图/媒体条、基础资料摘要、游玩记录摘要。
5. 低调操作：编辑档案、选择 Hero 媒体、清除 Hero 媒体。现有完整编辑能力继续由原 `GameDetailDialog` 承担，避免在本版本重写所有编辑逻辑。

## Hero 媒体来源与回退
新增可持久化字段 `archive_media_path`，由终端拥有并复制到 `game_assets/archive/`。支持 JPG/JPEG/PNG/WebP/BMP/GIF，不支持视频。

显示优先级：
1. `archive_media_path`（用户专门指定的档案展示媒体）
2. `preview_gif_path`（已有海报墙 GIF 动态预览）
3. `screenshot_directory` 中最近修改的受支持图片/GIF
4. 无媒体时使用主题背景/渐变占位

封面 `cover_path` 不参与 Hero 回退，避免在档案页重复海报墙封面。

## 内部“染色/玻璃感”
本版先采用低风险的软件层染色：从当前 Hero 源取静态颜色样本（GIF 使用首帧），把少量综合色调混入档案内容背景；Hero 自身叠加暗化渐变保证标题可读。暂不做全页实时模糊，避免为第一版档案页引入高开销渲染链路。该效果不改变顶层窗口材质，不依赖 Windows DWM。

如果媒体读取失败，直接回退主题背景，不阻止打开档案页。

## 数据兼容
- `GameMetadata` 增加可选字段 `archive_media_path`。
- JSON 仍保持兼容读取：旧 JSON 缺失字段时默认为 `None`。
- SQLite `games` 表增加 `archive_media_path` 列，数据库 schema version 从 3 升到 4；初始化时对旧库执行增量 `ALTER TABLE`。
- `GameAssetService` 增加 archive 媒体导入/清除；删除游戏档案时一并删除终端拥有的 Hero 资源。
- 备份格式仍保持 v3；开启“视觉资源”备份时，`game_assets/archive/` 与 covers/previews 一并写入和恢复。旧 v1/v2/v3 备份缺少 archive 目录时按空目录兼容，不影响恢复。

## 主窗口导航行为
- 右键“游戏档案”切换到游戏档案内容页，不再直接 `exec()` 游戏档案对话框。
- 页面 `←` 返回海报墙。
- 切换“影片/游戏”主轴时，如果当前在游戏档案页，先返回库页面，再完成库切换。
- 保存/编辑后刷新当前档案页和海报墙数据；游玩会话结束触发库刷新时，若档案页仍打开，也同步刷新游玩统计。

## 测试
- 数据模型/JSON/SQLite 对旧数据向后兼容。
- Hero 资源只接受图片/GIF，拒绝视频。
- Hero 回退顺序可独立测试。
- 主窗口源码回归：游戏档案使用内容页切换，存在左上角返回路径，影片逻辑不改。
- 完整 pytest、compileall、累计覆盖包还原比对、ZIP 完整性检查。
